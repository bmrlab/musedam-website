## Find an endpoint

For your first integration, follow the [Quick start](./product-library) to obtain access and make your first request. This page groups endpoints by resource and provides their parameters, requests, and responses.

Base URL: `https://open.musedam.cc/api/product`. Append an endpoint path to call it. Replace `your_api_key` and example resource IDs with your own values.

### List brands

**Endpoint**: /brands

**Method**: GET

**Description**: Returns public metadata ordered by sortOrder then id. Raw logo URLs are excluded.

Required role: view_only, usable, editable or manage.

**Request parameters**:

| Parameter | Type | Required | Description |
| - | - | - | - |
| page | Integer | No | Query parameter. Ordinary page number. Not allowed when sync=true. Excessive offset causing integer overflow is rejected. Minimum: 1; Default: 1 |
| pageSize | Integer | No | Query parameter. Page size; values above 100 are capped at 100. Nonpositive/noninteger values are rejected. Minimum: 1; Default: 20 |

**Response fields**:

| Field | Type | Description |
| - | - | - |
| success | Boolean | true on success. |
| data | List&lt;Brand&gt; | Returned data; fields are listed below. |

## Permissions and data scope

- Complete [Get access](./product-library#authentication-and-scope) first. Each request uses the key's team and the collaborator's current role, not the key creator's permissions.
- Request parameters cannot switch teams, libraries or operators. The Product Library API does not manage keys or collaborators.
- Removing a collaborator does not delete existing shares or history. Use [Revoke a share](#operation-revokeProductShare) to stop sharing. See [Error codes](./product-library-write-conventions#error-catalog) for inactive credentials or unavailable authentication.

## Responses and pagination

JSON endpoints use the following structure. Successful downloads and exports return files directly.

| Result | How to read it |
| --- | --- |
| Success | `success: true`; read the result from `data`. `code` and `message` are `null`. |
| Failure | `success: false` and `data: null`. Handle the HTTP status and `code`; do not depend on the wording of `message`. |
| Validation failure | If the response includes `details`, use `details[].field` and `details[].message` to correct the fields. |
| Request tracing | Keep `requestId` or the `X-Request-Id` response header for troubleshooting. |

Ordinary lists accept `page` and `pageSize` and return a top-level `pagination` object:

| Parameter | Default | Range |
| --- | --- | --- |
| `page` | `1` | Integer starting at `1`. |
| `pageSize` | `20` | Positive integer; values above `100` are capped at `100`. |

```json
{
  "page": 1,
  "pageSize": 20,
  "totalCount": 42,
  "totalPages": 3
}
```

Products and assets can become invisible during a request. A page may therefore contain fewer than `pageSize` records while retaining its original counts. Reading an invisible individual resource returns `404`.

Use [cursor synchronization](./product-library-synchronization) to maintain a product copy; ordinary page numbers are for browsing. See each endpoint for filters. Ordinary queries ignore unknown parameters; JSON request bodies reject unknown fields.

### Field formats

| Field | Usage |
| --- | --- |
| Numeric resource IDs | Positive integers up to `2147483647`. |
| Template, group, field and version IDs | Strings; preserve them as received and do not assume UUID format. |
| Asset IDs | Use `id` from asset lookup (FilePath ID), not an AssetObject ID or product association ID. |
| Category `iconAssetId` | A category icon identifier (CategoryIconAsset). |
| `size` | Decimal string or `null`, preserving large byte counts. |
| Dates | RFC 3339 strings or `null`; preserve all six fractional digits in synchronization timestamps. |
| Product SKU | The API field is named `spu`. |

Legacy or unresolved product media can have `id: null`. Valid media references are not truncated. See [Media links](./product-library-product-writes#media-and-expiry) for previews and downloads.

All responses include `Cache-Control: private, no-store`. JSON operations and errors use `application/json`. See [Request limits](./product-library-write-conventions#request-limits) for request size and batch limits.
