## Quick start

The Product Library API is available at `https://open.musedam.cc/api/product`. Append an endpoint path, such as `/products`, to this address.

1. Obtain a MuseDAM API Key.
2. Ask a Product Library manager to add the key as an API Key Collaborator in **Member settings → Add member** and assign the required role.
3. Call the API from your server with an `Authorization: Bearer <key>` header.

Authorization uses the key’s team and the collaborator’s current role. Request parameters cannot switch product libraries.

New collaborators have the `view_only` role by default. Choose a role for the operations you need:

| Role | Available operations |
| --- | --- |
| `view_only` | View published products. |
| `usable` | View, share and download published products. |
| `editable` | Create and edit products, access drafts, publish and delete products. |
| `manage` | Manage all resources, including brands, categories, information templates and activity records. |

Each role includes the preceding role’s permissions. Replace resource IDs in the examples with actual IDs.

Replace `your_api_key` with your authorized API Key to query the product list:

```bash
curl --request GET 'https://open.musedam.cc/api/product/products?page=1&pageSize=20' \
  --header 'Authorization: Bearer your_api_key'
```

A successful response has `success: true`, a product list in `data`, and paging information in `pagination`. If the list is empty, check whether the library contains products visible to your role; `view_only` and `usable` can only view published products.

## Requests and responses

Every request uses `Authorization: Bearer <key>`. JSON requests use `Content-Type: application/json`. Endpoint paths below are relative to the service address.

JSON endpoints use the following structure. Successful downloads and exports return files directly.

| Result | How to read it |
| --- | --- |
| Success | `success: true`; read the result from `data`. `code` and `message` are `null`. |
| Failure | `success: false` and `data: null`. Handle the HTTP status and `code`; do not depend on the wording of `message`. |
| Validation failure | If the response includes `details`, use `details[].field` and `details[].message` to correct the fields. |
| Request tracing | Keep `requestId` or the `X-Request-Id` response header for troubleshooting. |

Ordinary lists accept `page` and `pageSize` and return a top-level `pagination` object. `totalCount` is the total record count; `totalPages` is the total page count:

| Parameter | Default | Range |
| --- | --- | --- |
| `page` | `1` | Integer starting at `1`. |
| `pageSize` | `20` | Positive integer; values above `100` are capped at `100`. |

```json
{
  "page": 1,
  "pageSize": 20,
  "totalCount": 42,
  "totalPages": 3
}
```

Products and assets can become invisible during a request. A page may therefore contain fewer than `pageSize` records while retaining its original counts. Reading an invisible individual resource returns `404`.

Use [cursor synchronization](#cycle-protocol) to maintain a product copy; ordinary page numbers are for browsing. See each endpoint for filters. Ordinary queries ignore unknown parameters; JSON request bodies reject unknown fields.

<details id="field-formats">
<summary>Field formats</summary>

| Field | Usage |
| --- | --- |
| Numeric resource IDs | Positive integers up to `2147483647`. |
| Template, group, field and version IDs | Strings; preserve them as received and do not assume UUID format. |
| Asset IDs | Use `id` from asset lookup (FilePath ID), not an AssetObject ID or product association ID. |
| Category `iconAssetId` | A category icon identifier (CategoryIconAsset). |
| `size` | Decimal string or `null`, preserving large byte counts. |
| Dates | RFC 3339 strings or `null`; preserve all six fractional digits in synchronization timestamps. |
| Product SKU | The API field is named `spu`. |

Legacy or unresolved product media can have `id: null`. Valid media references are not truncated. See [Media links](#media-and-expiry) for previews and downloads.

</details>

<details id="write-preconditions">
<summary>Concurrent updates</summary>

Save the strong `ETag` (including quotes) when reading a brand, category, template, or product. Supply it as `If-Match` for an update, status change, or deletion. On `412 precondition_failed`, read and reconcile again. If omitted, the later write takes precedence. Shares, history, and download records do not use ETag.

</details>

<details id="atomic-create-replay">
<summary>Creation and download retries</summary>

Resource creation accepts `Idempotency-Key`, scoped to the team, API key, and operation. Keys allow up to 255 characters and cannot be blank or contain control characters. Retry with the same key and input within 24 hours; changed input returns `409 idempotency_key_reused`. Resource creation replays the initial non-media result and rebuilds media using current permissions. Download retries reuse the record but authorize and transfer current files again.

</details>

<details id="error-catalog">
<summary>Request limits and errors</summary>

Request bodies are limited to 1 MiB. Unknown JSON properties are rejected. Ordinary queries ignore unknown parameters; history and sync queries use stricter validation.

| Result | Action |
| --- | --- |
| 401 / 403 | Check the key, collaborator role, and resource visibility. |
| 404 | The resource is missing, deleted, or inaccessible; check its ID. |
| 422 `validation_failed` | Correct the input. If `details` is present, read `field` and `message`. |
| 409 `sku_in_use` / `name_in_use` | Change the conflicting SKU or name. Soft-deleted products still reserve their SKU. |
| 409 `mutation_response_unavailable` | The mutation committed or replayed. Check `mutationOutcome`; do not blindly create again. |
| 503 `write_conflict` | The mutation rolled back. Wait according to `Retry-After: 1`, then retry. |
| 413 | Reduce the body or download count/size. |

Use `X-Request-Id` or the JSON `requestId` for troubleshooting. A download error with `mutationOutcome` means the record committed; retain the original idempotency key when retrying.

</details>

## Categories

<details id="category-rules">
<summary>Category trees and deletion</summary>

Sibling names must be unique, and parents must belong to the same brand. A brand allows at most 10 levels and 5000 nondeleted nodes. `sortOrder` is a zero-based sibling position: omission appends new or moved categories and preserves position for same-parent updates. Renaming or moving updates descendant paths.

Creation adds a direct library-default template binding only when that template has no brand bindings or includes this brand. Otherwise creation still succeeds, with ancestor, brand, then library-default resolution. Deletion soft-deletes the entire subtree; any nondeleted product in it causes `409 category_has_products` without deleting anything.

</details>

## Information templates

<details id="template-groups">
<summary>Groups</summary>

`groups` contains 1–200 groups. A template may have at most 200 fields in total.

| Field | Type | Description |
| --- | --- | --- |
| `id` | string | Required for an existing group, 1–128 characters, belonging to this template. Omit for a new group. |
| `name` | string | Required, 1–128 characters. Leading and trailing whitespace is trimmed. |
| `fields` | array | Required. Fields in the group, described below. |

Existing groups keep their stored order; new groups append in the supplied order. Groups do not accept `sortOrder` or `isDefault`. The server assigns the default group, which cannot be deleted.

</details>

<details id="template-fields">
<summary>Fields</summary>

New fields require `key`, `name`, and `type`. Existing fields require `id`. When the type is unchanged, omitted properties retain their values, except for `sortOrder`. Changing `type` migrates `config` for the target type; provide new configuration when required.

| Field | Type | Description |
| --- | --- | --- |
| `id` | string | Required for an existing field, 1–128 characters, belonging to this group. Omit for a new field. |
| `key` | string | Required for a new field, 1–64 characters. A unique, valid identifier; cannot change for existing fields. |
| `name` | string | Required for a new field, 1–128 characters. |
| `type` | string | Required for a new field. Supported types appear in the configuration table below. |
| `required` | boolean | Optional. Defaults to `false` for a new field. |
| `placeholder` | string or null | Optional, up to 255 characters. Defaults to `null` for a new field. |
| `sortOrder` | integer | Optional, nonnegative, and unique within the group. If omitted, uses the field's array position. |
| `config` | object | Depends on the field type; see below. Defaults to `{}` for a new field, but must still meet that type's configuration requirements. |
| `typeChangeConfirmed` | boolean | Optional. Set to `true` for an allowed type change that requires confirmation. |

Creation seeds three protected fields: name, SKU, and main image. This leaves room for up to 197 custom fields. Custom fields in the first group follow those three fields: their supplied `sortOrder` (or array position when omitted) is increased by 3. Replacement definitions must keep these field IDs, types, required flags, and configurations. Fields cannot move between groups.

New fields must be custom fields and cannot use reserved system keys. `isSystemField` and `systemKey` cannot create or reassign system identities; preserve their values on update. Unknown group or field properties are rejected.

</details>

<details id="field-configuration">
<summary>Field configuration</summary>

`config` depends on the field's `type`. For example, text fields use `{}`, while currency and choice fields need additional configuration.

| Field type | Configuration |
| --- | --- |
| `text`, `textarea`, `email`, `phone`, `url`, `color`, `date`, `dateRange` | Use `{}`. Other configuration properties are not accepted. |
| `number` | Optional `unit`, a string. |
| `currency` | Required `code` and `symbol` (nonempty strings), and `decimals` (an integer from 0 to 4). |
| `richtext` | Required `mode`, either `html` or `delta`. |
| `select`, `radio`, `checkbox` | Required, nonempty `options` array. Entries follow the table below; `value` must be unique. |
| `image`, `file` | Optional `maxCount` (an integer of at least 1), `maxSizeMB` (a number greater than 0), and `accept` (an array of strings). |

Each `options` entry contains:

| Field | Type | Description |
| --- | --- | --- |
| `value` | string | Required, nonempty. The option's unique value. |
| `label` | string | Required, nonempty. The display label. |
| `sortOrder` | integer | Required, nonnegative. |
| `archived` | boolean | Optional. Whether the option is archived. |

System fields support `customPlaceholder`, an optional string of up to 255 characters. System brand and category fields do not accept custom options. Protected system fields cannot change their configuration.

Empty and system configurations reject unknown properties. Other configuration and option validators strip unknown properties. Download the [OpenAPI JSON](/assets/developers/product-library/openapi.json) for the full machine-readable definition.

</details>

## Products

<details id="template-pins-and-field-values">
<summary>Pinned templates and custom fields</summary>

Products save a template version at creation. Interpret `templateFields` using `templateDefinition`; later template edits or deletion do not change that version. Ordinary PATCH cannot change the template. `templateFields` uses pinned field IDs as keys and shallow-merges on update; `null` clears an individual value.

An explicit `templateId` takes priority. Otherwise a supplied `categoryId` resolves the category, ancestors, brand, then library default. Without a category, only the library default is considered, even when a brand is supplied.

| Field type | Input format |
| --- | --- |
| `number`, `currency` | JSON number |
| `dateRange` | Ordered pair of date strings |
| `checkbox` | Array of option values |
| `image`, `file` | Array of FilePath IDs, or null |
| `richtext` | String in HTML mode; `{ "ops": [...] }` in delta mode |

Drafts may omit required values, but supplied and merged fields must meet type and option rules. Publishing or editing a published product validates the complete product. A write may reference at most 100 media items across all fields, using existing same-library FilePath IDs. Omitted media lists stay unchanged; `[]` clears them. Without `coverAssetId`, the first `imageAssetIds` image becomes the cover.

</details>

<details id="cycle-protocol">
<summary>Synchronization and checkpoints</summary>

1. Start with `sync=true`, omitting `updatedAfter` for a full scan. For an incremental cycle, use the previous completed `syncedUntil`.
2. Merge by product `id` and `updatedAt`, retaining the newer version.
3. Follow `nextCursor` with `sync=true&cursor=...` until null, including when `data` is empty.
4. Save the completed `syncedUntil` unchanged, not the last product timestamp.

Cursors bind the key, role, library, filters, and page size; keep them unchanged while paging. Start a new cycle after authorization or filter changes, and scan fully when the scope expands. Preserve all six fractional digits in checkpoints and sync `updatedAt`; JavaScript Date loses precision. Each cycle reads current state in `[updatedAfter, syncedUntil)`, with the first request’s server time minus 30 seconds as its upper bound. Longer transactions may still affect completeness; this is not an event stream of every change.

</details>

<details id="reconciling-removals">
<summary>Removing deleted or invisible products</summary>

Sync does not return deletion events. Periodically send local product IDs to [visibility checking](#operation-checkProductVisibility), removing local copies marked `not_visible`. Visibility does not check business filters such as brand, category, or search. For a filtered replica, periodically reconcile the full filtered result or sync all visible products and filter locally.

</details>

<details id="media-and-expiry">
<summary>Preview and download links</summary>

Use `previewUrl` to display product media. For originals, check `downloadUrl` or use the download operations below; preview access does not establish download permission.

| Link | Availability | Maximum service-issued lifetime |
| --- | --- | --- |
| Derived preview | Appropriate viewing permission | 3600 seconds |
| Original-image preview fallback | Images only; may also be returned to `view_only` | 300 seconds |
| `downloadUrl` | Resolvable, visible association; `usable` or higher plus `products:read` and `products:download` | 300 seconds |

Every service-issued link is also bounded by the API key's expiry. Fetch product data again after a link expires; do not persist signed URLs as asset identifiers.

<details id="product-media-fields">
<summary>Which fields do covers, images, and related assets return?</summary>

`cover` is one media object, or null when there is no cover. `images` and `relatedAssets` are arrays of media objects. Custom image/file values may be arrays or null; unset fields may be omitted.

| Field | Type | Description |
| --- | --- | --- |
| `id` | Integer or null | ID returned by asset lookup (FilePath ID), not an AssetObject ID or product-asset association ID |
| `name`, `mimeType` | String or null | File name and MIME type |
| `size` | String or null | Decimal byte count, such as `"2048"`; never a JSON number |
| `width`, `height`, `duration` | Number or null | Media dimensions and duration |
| `previewUrl` | URL or null | Preview for display; null when unavailable |
| `downloadUrl` | URL or null; may be omitted | Original file URL; availability is described above |
| `downloadUrlExpiresAt` | Timestamp or null; may be omitted | Download URL expiry in RFC 3339 format |

</details>

<details>
<summary>How do missing links, legacy media, and external previews behave?</summary>

- Non-image assets only return derived previews. Original PDFs, archives, and documents never serve as preview fallbacks. Library asset lookup and template configuration contain previews only.
- Missing download permission or an unresolved association omits `downloadUrl` and `downloadUrlExpiresAt`. With permission but an unavailable original, those values may be null.
- Stored external DAM thumbnails or previews are returned only to API keys without expiry, after excluding known original URLs. The provider controls their lifetime; short expiry and provider-signature validation are not guaranteed.
- For an API key with `expiresAt`, an external preview whose expiry cannot be verified is null. Signature-like query parameters are not a trusted expiry source.
- Service-issued URLs keep the limits above. Signing failure never falls back to a raw storage URL.

</details>

</details>

<summary>ProductSummary response fields</summary>

### List or synchronize products

**Endpoint**: /products

**Method**: GET

**Description**: Ordinary pagination orders updatedAt/id descending. sync=true uses ascending (updatedAt,id), inclusive lower and exclusive fixed upper bound (PostgreSQL clock minus 30 seconds). **Endpoint**: /products

**Method**: POST

**Description**: Creates draft only. Resolves and pins a template version at creation; template fields validate against that immutable definition. ### Download one product original

**Endpoint**: /products/&#123;id&#125;/download-assets/&#123;assetKey&#125;

**Method**: GET

**Description**: Fetches one current product original identified by an encoded candidate key. Requires a Bearer header and current read/download authorization; the URL contains no API-key secret. Creates a business record before delivery. Optional 24-hour idempotency is scoped separately from POST downloads, reuses the record, and still reauthorizes and transfers current bytes.

Required role: usable, editable or manage.

**Request parameters**:

| Parameter | Type | Required | Description |
| - | - | - | - |
| id | Integer | Yes | Path parameter. Positive signed 32-bit resource ID. Positive integer ID, maximum 2147483647. |
| assetKey | String | Yes | Path parameter. URL-encoded selection key returned by the product download-candidate list. Not a FilePath or AssetObject ID. Minimum length 1 characters; Maximum length 256 characters |
| Idempotency-Key | String | No | Optional header. Retry the same key and input within 24 hours; see [Idempotent retries](#atomic-create-replay). |

**Response fields**: `200`. Success returns an attachment containing file bytes. Errors before delivery use JSON.

Response headers: `Content-Disposition`, `X-Download-Record-Id`, `X-Idempotency-Replayed`

Request example:

The example uses the download-candidate key p40:a2, encoded as p40%3Aa2 in the URL. Use the key returned by your download-candidate list; it is not a FilePath or AssetObject ID.

```bash
curl --request GET \
  'https://open.musedam.cc/api/product/products/40/download-assets/p40%3Aa2' \
  --header 'Authorization: Bearer your_api_key' \
  --output product-asset.bin
```
