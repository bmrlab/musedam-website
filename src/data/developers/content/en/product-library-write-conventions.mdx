## Write preconditions

All paths use the Base URL `https://open.musedam.cc/api/product`. The current API Key Collaborator role authorizes each operation. Supplying a team, library, actor or operation allowlist in the request cannot grant access.

Read the resource before updating it and preserve its strong `ETag`. Send that exact value in `If-Match` with PATCH, status changes or DELETE. A stale or weak tag returns `412 precondition_failed` without changing the resource. `*` or a comma-separated list containing the current strong tag also matches. Omitting the header uses last-writer-wins behavior. Sharing, history and recorded downloads do not use ETag or If-Match.

## Creation and idempotent retries

Resource creates accept an optional `Idempotency-Key`, scoped to the team, API key and operation for 24 hours. Use a nonblank value of at most 255 characters without ASCII control characters. Retry an uncertain create with the same key and input. Different canonical input under the same key returns `409 idempotency_key_reused`.

A replay preserves the original non-media result and ETag even after a later edit. Media URLs are issued again only after checking current permissions, visibility and associations. Deleted or invisible products cannot be restored through a replay. New media associations do not become part of the original result. Use a new key only for a new logical operation.

## Partial updates

Omitted fields are preserved. Explicit `null` clears only nullable fields. Product `templateFields` are shallow-merged by custom field ID; null clears an individual value. Template `groups` replace the complete definition when supplied. Preserve existing group and field IDs, including protected system fields. Unknown JSON properties are rejected.

## Brands

Brand writes require a `manage` API Key Collaborator. Create accepts `name`, `description` and `logoUrl`; PATCH accepts a nonempty subset. Names are trimmed, nonempty and at most 128 characters. Descriptions are nullable and at most 512 characters. Logo references must use permitted storage/CDN hosts and HTTP(S) without embedded credentials. Query signatures are removed before storage. No upload or remote import occurs.

Brand responses omit `logoUrl`. They contain `id`, `name`, `code`, `description`, `website`, `sortOrder`, `isEnabled`, `createdAt` and `updatedAt`. Names need not be unique. The server generates the unique library-scoped code; clients cannot set it. Exhausted code conflicts return `409 code_in_use`.

Deletion returns `409 brand_has_dependents` if a nondeleted category or product still references the brand. Reassign or remove those dependencies first.

## Write outcomes and recovery

Rolled-back lock conflicts return `503 write_conflict` with `Retry-After: 1`. Wait before retrying, keep the same idempotency key for a create, and refresh stale preconditions when needed.

If the mutation commits but its response cannot be prepared, the API returns `409 mutation_response_unavailable`, `success: false`, `data: null` and `mutationOutcome: committed` (or `replayed`). No ETag or media URL is returned. The mutation was not rolled back. Reconcile through an authorized read or the original idempotency key instead of blindly repeating it.

Accepted downloads and exports may return their specific preparation or delivery error with `mutationOutcome`. Keep the original idempotency key when retrying that accepted operation. `requested` records acceptance, not completed transfer or a saved local file.

## Troubleshooting

For `401` or `403`, correct the API key or collaborator role. For `422`, inspect `details[].field` and fix the input. Preserve `X-Request-Id` or the JSON `requestId` for support. Do not log credentials or signed media URLs. See the [error catalog](./product-library-reference#error-catalog) and [API documentation](./product-library-reference).
