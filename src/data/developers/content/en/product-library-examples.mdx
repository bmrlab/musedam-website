Use each example independently. Replace `your_api_key` with your API key and the example resource IDs with IDs from your Product Library.

## List products

Add the key as an API Key Collaborator first. See [getting access](./product-library#authentication-and-scope). This request lists products visible to the current role.

```bash
curl --request GET 'https://open.musedam.cc/api/product/products?page=1&pageSize=20' \
  --header 'Authorization: Bearer your_api_key'
```

Read products from `data` and paging information from `pagination`. The `view_only` and `usable` roles can only read published products.

## Create brands, categories and templates

Creating a brand requires the `manage` role.

```bash
curl --request POST 'https://open.musedam.cc/api/product/brands' \
  --header 'Authorization: Bearer your_api_key' \
  --header 'Content-Type: application/json' \
  --data-raw '{"name":"Example brand"}'
```

The response returns the brand ID in `data.id`. See [product categories](./product-library-categories) and [product information templates](./product-library-template-writes) for their creation parameters. Reuse existing resources when they already meet your needs.

## Find assets

Find an existing image before creating or editing a product. This endpoint requires `editable` or `manage`.

```bash
curl --request GET 'https://open.musedam.cc/api/product/assets?mimeType=image%2F&pageSize=20' \
  --header 'Authorization: Bearer your_api_key'
```

Use the returned asset `id` in `coverAssetId` or `imageAssetIds`. Use `previewUrl` to display a preview.

## Create a product

Creating a product requires `editable` or `manage`. This example uses brand `10`, category `20` within that brand and image asset `30`. Replace these with existing resource IDs.

```bash
curl --request POST 'https://open.musedam.cc/api/product/products' \
  --header 'Authorization: Bearer your_api_key' \
  --header 'Content-Type: application/json' \
  --header 'Idempotency-Key: create-product-001' \
  --data-raw '{"name":"Example product","spu":"EXAMPLE-001","brandId":10,"categoryId":20,"coverAssetId":30,"imageAssetIds":[30]}'
```

The new product is a draft. Read its ID from `data.id`. When retrying the same creation, keep the request body and `Idempotency-Key` unchanged. Use a new idempotency key to create another product.

## Update and publish a product

Update the description of product `40`:

```bash
curl --request PATCH 'https://open.musedam.cc/api/product/products/40' \
  --header 'Authorization: Bearer your_api_key' \
  --header 'Content-Type: application/json' \
  --data-raw '{"description":"New product description"}'
```

Omitted fields keep their values. Send `null` to clear a nullable field or `[]` to clear a media list. To prevent overwriting concurrent changes, send the `ETag` returned by a read in the `If-Match` header. See [writes and error handling](./product-library-write-conventions).

Publish product `40`:

```bash
curl --request PATCH 'https://open.musedam.cc/api/product/products/40/status' \
  --header 'Authorization: Bearer your_api_key' \
  --header 'Content-Type: application/json' \
  --data-raw '{"status":"published"}'
```

Fill the template’s required fields and make sure its assets are available before publishing. Validation failures return `422` with field details and leave the product unchanged.

## Read product details and previews

Read the details of product `40`:

```bash
curl --request GET 'https://open.musedam.cc/api/product/products/40' \
  --header 'Authorization: Bearer your_api_key'
```

Display product media with `previewUrl`. With download permission, media may also include `downloadUrl` and `downloadUrlExpiresAt`. Read the product again when a link expires.

## Share, export and download

Create a seven-day share for published product `40`, with downloads disabled. This requires `usable` or higher:

```bash
curl --request POST 'https://open.musedam.cc/api/product/product-shares' \
  --header 'Authorization: Bearer your_api_key' \
  --header 'Content-Type: application/json' \
  --data-raw '{"productIds":[40],"expiresInDays":7,"allowDownload":false}'
```

The share URL is returned in `data.url`.

Export product `40` to Excel. This requires `usable` or higher:

```bash
curl --request POST 'https://open.musedam.cc/api/product/product-downloads' \
  --header 'Authorization: Bearer your_api_key' \
  --header 'Content-Type: application/json' \
  --data-raw '{"kind":"export","productIds":[40],"format":"xlsx","includeAssetUrls":false}' \
  --output 'products.xlsx'
```

The example saves `products.xlsx` without asset links. The `format` field also supports `csv` and `json`.

Download the original files for product `40`. This requires `usable` or higher:

```bash
curl --request POST 'https://open.musedam.cc/api/product/product-downloads' \
  --header 'Authorization: Bearer your_api_key' \
  --header 'Content-Type: application/json' \
  --data-raw '{"kind":"assets","productIds":[40]}' \
  --output 'product-download'
```

The result is saved as `product-download`. A single file is returned in its original format; multiple files are returned as a ZIP. Adjust the filename for the returned file type.

## Understand product template versions

A product saves the template version used at creation. Later template edits or deletion do not change that product’s field definitions. Read that version from `templateDefinition` in the product details. See [product information templates](./product-library-template-writes).

## Synchronize products

Start the first synchronization with this request:

```bash
curl --request GET 'https://open.musedam.cc/api/product/products?sync=true&pageSize=100' \
  --header 'Authorization: Bearer your_api_key'
```

If `pagination.nextCursor` is not `null`, replace `your_cursor` below with its complete value to fetch the next page:

```bash
curl --get 'https://open.musedam.cc/api/product/products' \
  --header 'Authorization: Bearer your_api_key' \
  --data-urlencode 'sync=true' \
  --data-urlencode 'cursor=your_cursor'
```

Continue with each returned `nextCursor` until it is `null`, even when a page has an empty `data` array. After processing every page, save `pagination.syncedUntil` unchanged. In the next cycle, pass it as `updatedAfter` in the first request. Keep the timestamp’s full precision. See [product synchronization](./product-library-synchronization) for the complete rules.

## Check product visibility

Synchronization does not return records for deleted products. Periodically check product IDs stored locally:

```bash
curl --request POST 'https://open.musedam.cc/api/product/products/visibility' \
  --header 'Authorization: Bearer your_api_key' \
  --header 'Content-Type: application/json' \
  --data-raw '{"ids":[40,41]}'
```

Remove products reported as `not_visible` from your local copy. This status can also mean a draft is hidden or access is unavailable; it does not establish whether a product exists. To delete a product itself, see [product writes and publishing](./product-library-product-writes).

## Handle common errors

| Status | Action |
| --- | --- |
| 401 / 403 | Check the API key status and collaborator role. |
| 412 | Read the product again, review the changes and retry with the new ETag. |
| 422 | Fix the parameters identified by `details[].field` and `details[].message`. |
| 409 | Handle the conflict using `code`. For `mutation_response_unavailable`, read and verify the result first. |

Keep the response `requestId` for troubleshooting. See the complete [error codes](./product-library-reference#error-catalog).
