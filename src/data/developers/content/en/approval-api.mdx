## Approval Open API

- `POST https://muse-open.test.tezign.com/api/muse/approval-api`

## Request conventions

- Method: `POST`
- `Content-Type`: `application/json`
- Body must be valid JSON
- Use `service` to select the capability

Supported `service` values:

- `subscriptionQuery`
- `subscriptionChange`
- `listTemplates`
- `createApproval`
- `taskStatusQuery`

## Unified response

```json
{
  "code": "0",
  "message": "success",
  "result": {},
  "traceId": "trace_xxx"
}
```

Common error codes:

- `400`: invalid payload
- `401`: authentication failed
- `403`: permission denied
- `404`: resource not found
- `500`: internal error

## listTemplates

Request:

```json
{
  "service": "listTemplates"
}
```

`result` is an array of templates with fields such as:
`id`, `name`, `description`, `enabled`, `usageCount`, `autoImportEnabled`, `targetFolder`, `workflow`.

## createApproval

Required fields:

- `templateId`
- `createdBy`
- `assets` (at least one item)
- `assets[].url` must be a public `http/https` URL

Request example:

```json
{
  "service": "createApproval",
  "templateId": "101",
  "createdBy": "10086",
  "assets": [
    {
      "name": "demo.mp4",
      "url": "https://cdn.example.com/m/asset_1.mp4"
    }
  ]
}
```

Success example:

```json
{
  "code": "0",
  "message": "success",
  "result": {
    "taskId": "9527"
  }
}
```

## taskStatusQuery

Request:

```json
{
  "service": "taskStatusQuery",
  "taskId": "9527"
}
```

`result.status` values:
`PENDING | PROCESSING | APPROVED | REJECTED | CANCELED`.

## Subscription and callbacks

Check subscription:

```json
{
  "service": "subscriptionQuery"
}
```

Add subscription:

```json
{
  "service": "subscriptionChange",
  "operation": "ADD",
  "callbackUrl": "https://example.com/webhook/approval"
}
```

Cancel subscription:

```json
{
  "service": "subscriptionChange",
  "operation": "DELETE"
}
```

### Callback payload specification

After `subscriptionChange` with `operation = ADD` succeeds, approval state changes are posted to your `callbackUrl`.

#### Callback request basics

- Method: `POST`
- `Content-Type`: `application/json`

Callback body:

```json
{
  "eventId": "evt_xxx",
  "eventType": "APPROVAL",
  "eventTime": "1760258885000",
  "payload": {
    "eventName": "TASK_APPROVED",
    "orgId": "233",
    "taskId": "9527",
    "taskStatus": "APPROVED"
  }
}
```

Field notes:

- `eventId`: unique event id (use as idempotency key)
- `eventType`: always `APPROVAL`
- `eventTime`: millisecond timestamp string
- `payload`: business payload

#### Common payload fields

Every callback `payload` contains at least:

- `eventName`
- `orgId` (system populated)
- `taskId`
- `taskStatus` (`PROCESSING` / `APPROVED` / `TIMEOUT`)

#### Full event set

- `NODE_STARTED`: when a node starts (first node, normal transition, or resubmit transition)
- `APPROVER_SUBMITTED`: when an approver submits a decision (can happen multiple times per node)
- `NODE_COMPLETED`: when a node is completed (approved/rejected)
- `NODE_TRANSFERRED`: when flow transfers to another processing node (normal/resubmit/timeout transfer)
- `SUBMITTER_RESUBMITTED`: when submitter uploads updated assets at resubmit step
- `TASK_APPROVED`: when task reaches final approved status
- `NODE_TIMEOUT`: when node times out (timeout transfer or re-assignment pending)

#### Field definitions

##### `payload.node`

- `nodeId` (`string`): node id
- `nodeOrder` (`number`): node order (present in some events)
- `nodeRole` (`string`): `normal` / `resubmit_submitter` / `resubmit_approver` (event-specific)
- `nodeStatus` (`string`): common values include `pending` / `processing` / `approved` / `rejected` / `timeout_transferred` / `re_assigned`
- `signMode` (`string`): `and` / `or` (event-specific)
- `approverCount` (`number`): approver count (event-specific)
- `approvers` (`array`): approver results on `NODE_COMPLETED`, item fields: `id`, `name`, `status`
- `startedAt` (`string`): ISO start time
- `completedAt` (`string`): ISO completion time
- `timeoutHours` (`number`): timeout threshold in hours (timeout events)

##### `payload.approver` (`APPROVER_SUBMITTED`)

- `id` (`string`): approver user id
- `name` (`string`): approver name
- `decision` (`approved` | `rejected`)
- `comment` (`string`)
- `submittedAt` (`string`, ISO)

##### `payload.submitter` (`SUBMITTER_RESUBMITTED`)

- `id` (`string`): submitter user id
- `name` (`string`): submitter name
- `comment` (`string`): resubmission comment
- `submittedAt` (`string`, ISO)

##### `payload.timeout`

- `transferTo` (`object | null`): timeout transfer target
  - when present: `{ "id": "...", "name": "..." }`
  - otherwise: `null`

##### `payload.latestAssets` (`SUBMITTER_RESUBMITTED`)

- `assetId` (`string`)
- `filePathId` (`string`)
- `version` (`number`)
- `oldStorePath` (`string`)
- `newStorePath` (`string`)
- `updatedAt` (`string`, ISO)

##### `payload.transferReason` (`NODE_TRANSFERRED`)

- `NEXT_NODE`: normal transition to next approval node
- `RESUBMIT_SUBMITTER`: transition to submitter resubmission node
- `RESUBMIT_APPROVER`: transition to approver re-review node after resubmission
- `TIMEOUT_TRANSFER`: transition after timeout transfer

#### Event sequence (key flows)

Delivery is at-least-once. Use `eventId` for idempotent processing.

##### Normal pass (multi-node)

1. `NODE_STARTED` (first node)
2. `APPROVER_SUBMITTED` (may repeat for each approver)
3. `NODE_COMPLETED`
4. If next node exists: `NODE_TRANSFERRED` -> `NODE_STARTED`
5. Repeat 2-4 until final node is complete
6. `TASK_APPROVED`

##### Rejected then resubmitted

1. `APPROVER_SUBMITTED` (`decision = rejected`)
2. `NODE_COMPLETED` (`nodeStatus = rejected`)
3. `NODE_TRANSFERRED` (`transferReason = RESUBMIT_SUBMITTER`)
4. `NODE_STARTED` (`nodeRole = resubmit_submitter`)
5. `SUBMITTER_RESUBMITTED`
6. `NODE_COMPLETED` (resubmission node)
7. `NODE_TRANSFERRED` (`transferReason = RESUBMIT_APPROVER`)
8. `NODE_STARTED` (re-review node)
9. Back to normal approval flow (`APPROVER_SUBMITTED` ...)

##### Timeout transfer / no transfer

1. Node timeout triggers `NODE_TIMEOUT` (`taskStatus = TIMEOUT`)
2. If timeout transfer target exists: `NODE_TRANSFERRED` (`transferReason = TIMEOUT_TRANSFER`) and task returns to `PROCESSING`
3. If no transfer target: only `NODE_TIMEOUT` (commonly `nodeStatus = re_assigned`) until manual follow-up
