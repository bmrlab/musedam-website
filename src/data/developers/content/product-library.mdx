## 快速接入

商品库全部 28 个操作统一使用 POST `https://open.musedam.cc/api/muse/product-api`。通过 `service` 指定下文的操作标识，所有业务参数放在扁平 JSON 请求体中。

1. 获取 MuseDAM API Key。
2. 请商品库管理员在「成员设置 → 添加成员」中，将该密钥添加为 API Key 协作者，并分配所需角色。
3. 从服务端调用接口，在请求头中携带 `Authorization: Bearer <APIKEY>`。

权限按密钥所属团队和协作者当前角色校验，请求参数不能切换商品库。

新添加的协作者默认为 `view_only`。按需要选择角色：

| 角色 | 可执行的操作 |
| --- | --- |
| `view_only` | 查看已发布商品。 |
| `usable` | 查看、分享和下载已发布商品。 |
| `editable` | 创建和编辑商品、访问草稿、发布及删除商品。 |
| `manage` | 管理全部资源，包括品牌、分类、信息模板及活动记录。 |

每个角色包含上一级角色的权限。后续示例中的资源 ID 需替换为实际值。

将 `your_api_key` 替换为已授权的 API Key，查询商品列表：

```bash
curl --request POST 'https://open.musedam.cc/api/muse/product-api' \
  --header 'Authorization: Bearer your_api_key' \
  --header 'Content-Type: application/json' \
  --data-raw '{
  "service": "listProducts",
  "page": 1,
  "pageSize": 20
}'
```

A successful JSON response has `code: "0"`, `message: "成功"`, `result.success: true`, products in `result.data`, and paging information in `result.pagination`. 列表为空时，先确认商品库中是否有当前角色可见的商品；`view_only` 和 `usable` 只能查看已发布商品。

## 请求与响应

所有请求均使用您自己的 MuseDAM API Key，携带 `Authorization: Bearer <APIKEY>` 和 `Content-Type: application/json`。全部操作使用相同的公共 POST 地址；资源 ID、分页、筛选和写入字段均为 JSON 请求体字段，与必填的 `service` 同级。

Successful JSON responses wrap the entire former v1 body in `result`; resource DTOs and business input fields are unchanged. The outer success fields are `code: "0"` and `message: "成功"`. Every failure is exactly `{code, message, result: null, traceId}`, with an existing nonzero numeric string `code` from the [error catalog](#error-catalog). Its specific business `message` includes field names and validation details when applicable. Failures have no nested response fields. HTTP statuses and control headers are unchanged.

| Field | Type | How to read it |
| --- | --- | --- |
| `code` | String | `"0"` on success; a nonzero numeric string on failure. |
| `message` | String | `"成功"` on success; a public error message on failure. Do not branch on its wording. |
| `result` | Object or null | The entire former v1 body on success; always null on failure. |
| `result.success` | Boolean, success only | `true`. |
| `result.data` | Object, array or null, success only | The service's unchanged resource DTO, list or mutation result. |
| `result.code` | Null, success only | Unchanged success field. |
| `result.message` | Null, success only | Unchanged success field. |
| `result.pagination` | Object, when present | Ordinary paging or synchronization metadata. |
| `result.requestId` | String, success only | Server request identifier, also exposed in `X-Request-Id`. |
| `traceId` | String | Correlation ID echoed in JSON and logged; falls back to the server request ID. |

Optionally send `traceId` alongside `service` in the request body. It must be a string of 1–128 characters matching `^[A-Za-z0-9._:-]+$`. A valid value is echoed as outer `traceId` and logged. Missing or invalid values use the server request ID for tracing; an invalid value still fails request validation, rather than being silently accepted. Preserve outer `traceId` and `X-Request-Id` when reporting a failure; `result.requestId` exists only on success. Tracing does not change authorization, HTTP statuses, or control headers.

The response examples use `trace_123` to illustrate a valid optional request `traceId`. If you omit it in a request example, expect the generated server request ID instead. `X-Trace-Id` carries the same correlation value.

Ordinary lists accept `page` and `pageSize` and return `result.pagination`. Its `totalCount` is the total record count; `totalPages` is the total page count. The following fragment shows only `result.pagination`, not a complete response:

| 参数 | 默认值 | 范围 |
| --- | --- | --- |
| `page` | `1` | 从 `1` 开始的整数。 |
| `pageSize` | `20` | 正整数，超过 `100` 时按 `100` 处理。 |

```json
{
  "page": 1,
  "pageSize": 20,
  "totalCount": 42,
  "totalPages": 3
}
```

商品和素材可能在请求期间变为不可见，因此实际返回条数可能少于 `pageSize`，计数仍保留分页时的结果。单项资源不可见时返回 `404`。

需要持续同步商品时，请使用[游标同步](#cycle-protocol)，不要依靠普通页码列表。筛选参数见具体接口；普通读取服务忽略未知业务字段，写入服务拒绝未知业务字段；历史和同步读取采用更严格的校验。

<details id="error-catalog">
<summary>请求限制与失败处理</summary>

请求体最多 1 MiB。写入服务拒绝未知业务字段，普通读取服务忽略未知业务字段；历史和同步读取服务严格校验。此规则按服务区分，与 HTTP 方法无关。

| 返回结果 | 处理方式 |
| --- | --- |
| 401 / 403 | 检查密钥、协作者角色及资源可见性。 |
| 404 | 资源不存在、已删除或不可访问，核对 ID。 |
| 422 `"42201"` | 根据 `message` 中的字段详情修正输入。 |
| 409 `sku_in_use` / `name_in_use` | 修改冲突的 SKU 或名称；软删除商品的 SKU 仍被占用。 |
| 409 `"40909"` | 变更已提交，核对当前状态；不要重复执行变更。 |
| 503 `write_conflict` | 变更已回滚，按 `Retry-After: 1` 等待后重试。 |
| 413 | 缩小请求体。 |

Use outer `traceId` and `X-Request-Id` for troubleshooting failures.



Outer `code` values are numeric strings. Error names below explain their meaning, not response fields. Use the HTTP status and outer code, not message wording, to choose recovery behavior.

| HTTP status | Outer `code` | Meaning | Action |
| --- | --- | --- | --- |
| 401 | `"40101"` | `invalid_credentials` | Check the API Key and Bearer header. |
| 503 | `"50301"` | `authentication_unavailable` | Credential validation is temporarily unavailable; retry later. |
| 401 | `"40102"` | `key_inactive` | Check whether the API Key is inactive or expired. |
| 403 | `"40301"` | `forbidden` | Check collaborator role and required permissions. |
| 404 | `"40401"` | `not_found` | Check the resource ID and current visibility. |
| 409 | `"40902"` | `sku_in_use` | Choose another SKU; soft-deleted products still reserve their SKU. |
| 409 | `"40903"` | `code_in_use` | Choose another resource code. |
| 409 | `"40904"` | `name_in_use` | Choose another resource name. |
| 409 | `"40905"` | `brand_has_dependents` | Remove or reassign dependent categories and products first. |
| 409 | `"40906"` | `category_has_products` | Remove or reassign dependent products first. |
| 409 | `"40907"` | `default_template_replacement_required` | Provide a replacement default template. |
| 413 | `"41302"` | `payload_too_large` | Reduce the request body to at most 1 MiB. |
| 422 | `"42201"` | `validation_failed` | Correct the input using field details in message. |
| 503 | `"50302"` | `write_conflict` | The mutation rolled back; wait according to Retry-After: 1, then retry. |
| 409 | `"40909"` | `mutation_response_unavailable` | The mutation committed; reconcile its state and do not repeat it. |
| 500 | `"50001"` | `internal_server_error` | Retain traceId and X-Request-Id for troubleshooting; reconcile state before retrying a write. |

Validation failure example (HTTP 422):

```json
{
  "code": "42201",
  "message": "Invalid request fields: name: Required",
  "result": null,
  "traceId": "trace_123"
}
```

Error detail wording is illustrative. An invalid request `traceId` is not echoed and still fails validation; outer `traceId` then uses the server request ID.

Mutation response unavailable example (HTTP 409):

```json
{
  "code": "40909",
  "message": "The mutation completed, but its response is unavailable. Do not repeat the mutation.",
  "result": null,
  "traceId": "trace_123"
}
```

For code `"40909"` (`mutation_response_unavailable`), reconcile the committed mutation instead of creating another resource. Do not repeat the mutation.

## 分类

<details id="category-rules">
<summary>分类树与删除</summary>

同级名称必须唯一，父分类必须属于同一品牌。分类最多 10 级，每个品牌最多 5000 个未删除节点。`sortOrder` 是从零开始的同级位置；创建或移动时省略则追加，同父级更新时省略则保持位置。改名或移动会更新后代路径。

创建时，只有商品库默认模板未绑定品牌或已绑定当前品牌，才添加直接模板绑定；否则仍创建成功，按祖先分类、品牌、商品库默认模板查找。删除会软删除整棵子树；其中有未删除商品时返回 `409 category_has_products`，不执行删除。

</details>

## 信息模板

<details id="template-groups">
<summary>分组 groups</summary>

`groups` 包含 1–200 个分组，一个模板的字段总数最多为 200。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 现有分组必填，1–128 个字符，必须属于本模板；新分组不传。 |
| `name` | string | 必填，1–128 个字符，去除首尾空白。 |
| `fields` | array | 必填，分组中的字段，见下表。 |

现有分组保持原有顺序，新分组按提交顺序追加。分组不接受 `sortOrder` 或 `isDefault`。默认分组由服务器指定，不能删除。

</details>

<details id="template-fields">
<summary>字段 fields</summary>

新字段必须提供 `key`、`name` 和 `type`。更新现有字段时必须传 `id`。类型不变时，省略的属性保留原值，`sortOrder` 除外；改变 `type` 时，`config` 会按目标类型迁移，必要时须显式提供新配置。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 现有字段必填，1–128 个字符，必须属于当前分组；新字段不传。 |
| `key` | string | 新字段必填，1–64 个字符，须为唯一的有效标识符；已有字段不能修改。 |
| `name` | string | 新字段必填，1–128 个字符。 |
| `type` | string | 新字段必填，支持的类型见下方配置表。 |
| `required` | boolean | 可选；新字段默认为 `false`。 |
| `placeholder` | string | 可选，最多 255 个字符；更新时省略以保留原值，新字段响应默认为 `null`。 |
| `sortOrder` | integer | 可选，同组内唯一的非负整数；省略时使用字段在数组中的位置。 |
| `config` | object | 按字段类型填写，见下方配置表；新字段省略时使用 `{}`，但仍须满足该类型的配置要求。 |
| `typeChangeConfirmed` | boolean | 可选；允许但需要确认的类型变更须传 `true`。 |

创建时会自动加入名称、SKU 和主图三个受保护字段，因此最多可新增 197 个自定义字段。第一个分组的自定义字段排列在这三个字段之后，传入的 `sortOrder`（省略时为数组位置）会增加 3。替换定义时须保留这些字段的 `id`，以及类型、必填标记和配置。字段不能移到其他分组。

新字段只能是自定义字段，不能使用保留的系统 key。`isSystemField` 和 `systemKey` 不能用于创建或重新分配系统身份；更新时保留原有身份。若提供 `systemKey`，必须是字符串：`name`、`sku`、`brand`、`category`、`description` 或 `mainImage`；自定义字段应省略它。未知的分组或字段属性会被拒绝。

</details>

<details id="field-configuration">
<summary>字段配置 config</summary>

配置由字段的 `type` 决定。例如，文本字段使用 `{}`，货币和选项字段需要额外配置。

| 字段类型 | config 配置 |
| --- | --- |
| `text`、`textarea`、`email`、`phone`、`url`、`color`、`date`、`dateRange` | 使用 `{}`，不接受其他配置。 |
| `number` | 可选 `unit`，字符串。 |
| `currency` | 必填 `code`、`symbol`（非空字符串）和 `decimals`（0–4 的整数）。 |
| `richtext` | 必填 `mode`，取值为 `html` 或 `delta`。 |
| `select`、`radio`、`checkbox` | 必填非空 `options` 数组。每项见下表，`value` 不得重复。 |
| `image`、`file` | 可选 `maxCount`（大于等于 1 的整数）、`maxSizeMB`（大于 0 的数字）和 `accept`（字符串数组）。 |

每个 `options` 元素包含：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `value` | string | 必填，非空，选项的唯一值。 |
| `label` | string | 必填，非空，显示名称。 |
| `sortOrder` | integer | 必填，非负整数。 |
| `archived` | boolean | 可选，是否归档该选项。 |

系统字段的可用配置是 `customPlaceholder`（可选字符串，最多 255 个字符）；品牌、分类系统字段不接受自定义选项。受保护系统字段的配置不能变更。

空配置和系统配置拒绝未知属性；其他配置及选项会移除未知属性。完整机器可读定义可下载 [OpenAPI JSON](/assets/developers/product-library/openapi.json)。

</details>

<details id="template-definition">
<summary>返回的模板定义</summary>

模板详情的 `groups` 和商品的 `templateDefinition.groups` 均包含分组与字段。商品返回的是创建时固定的版本，后续模板修改或删除不会改变它；未绑定模板时，`templateDefinition` 可为 `null`。

分组固定返回 `id`、`name`、`fields`，以及以下只读属性：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `isDefault` | boolean | 是否为默认分组。 |
| `sortOrder` | integer | 分组顺序。 |

每个字段固定返回 `id`、`key`、`name`、`type`、`required`、`placeholder`、`sortOrder`、`config`，以及以下属性；不返回写入参数 `typeChangeConfirmed`。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `isSystemField` | boolean | 是否为系统字段。 |
| `systemKey` | string 或 null | 系统身份：`name`、`sku`、`brand`、`category`、`description`、`mainImage`；自定义字段为 `null`。 |

`placeholder` 可为 `null`。配置中的媒体引用会返回安全的预览信息，不包含存储路径或凭据。读取商品的固定模板定义不需要 `templates:read` 权限。

## 商品

<details id="template-pins-and-field-values">
<summary>模板版本与自定义字段</summary>

商品创建时保存模板版本。读取 `templateDefinition` 解释 `templateFields`；后续模板变更或删除不影响这个版本，`updateProduct` 不能更换模板。`templateFields` 以固定版本中的字段 ID 为键，更新时浅合并；省略的值保持不变。富文本内部可包含 null。

显式 `templateId` 优先；否则，有 `categoryId` 时依次查找分类、祖先分类、品牌和商品库默认模板。没有分类时只考虑商品库默认模板，即使传入了品牌。

| 字段类型 | 输入格式 |
| --- | --- |
| `number`、`currency` | JSON 数字 |
| `dateRange` | 起止日期字符串组成的有序数组 |
| `checkbox` | 选项值数组 |
| `image`、`file` | FilePath ID 数组 |
| `richtext` | HTML 模式为字符串；delta 模式为 `{ "ops": [...] }` |

草稿可缺少必填值，但提交和合并后的字段仍须满足类型/选项规则；发布或编辑已发布商品会校验完整商品。一次写入的全部媒体引用合计最多 100 个，只接受本商品库现有的 FilePath ID。媒体列表省略时保留，`[]` 清空；未传 `coverAssetId` 时，首张 `imageAssetIds` 图片成为封面。

</details>

<details id="cycle-protocol">
<summary>同步与检查点</summary>

1. 首次使用 `"sync": "true"`，省略 `updatedAfter`；增量周期传入上次完成的 `result.pagination.syncedUntil`。
2. 按商品 `id` 和 `updatedAt` 合并，保留较新版本。
3. 使用 `"sync": "true", "cursor": "<nextCursor>"` 跟随 `result.pagination.nextCursor` 直到 null；即使 `result.data` 为空，也要继续。
4. 完成后原样保存 `result.pagination.syncedUntil`，不要改用最后一条商品的时间。

游标绑定密钥、角色、商品库、筛选条件和页大小；续页时不要改变它们。更换授权或筛选条件要开始新周期；范围扩大时重新全量同步。检查点和同步 `updatedAt` 保留完整六位小数，不要用 JavaScript Date 截断精度。每周期读取当前状态的 `[updatedAfter, syncedUntil)`，上界为首次请求时服务端时间减 30 秒；长事务仍可能影响完整性，不提供每次变更的事件流。


Synchronization returns items in `result.data` and metadata in `result.pagination`: `mode`, `syncedUntil` and `nextCursor`. Copy the returned `result.pagination.nextCursor` into the next request’s `cursor` field; do not rename request fields or wrap business input in `result`.

</details>

<details id="reconciling-removals">
<summary>清理已删除或不可见的商品</summary>

同步不会返回删除事件。定期将本地商品 ID 交给[可见性接口](#operation-checkProductVisibility)，`not_visible` 时移除本地副本。该接口不检查品牌、分类或搜索等业务筛选；若只维护筛选后的副本，须定期全量核对筛选结果，或同步全部可见商品后在本地筛选。

</details>

<details id="media-and-expiry">
<summary>预览与下载链接</summary>

展示商品媒体时使用 `previewUrl`。需要原文件时，检查 `downloadUrl`；能预览不等于有下载权限。

| 链接 | 返回条件 | 服务签发链接的有效期上限 |
| --- | --- | --- |
| 派生预览 | 具备相应查看权限 | 3600 秒 |
| 图片原图预览回退 | 仅适用于图片，`view_only` 也可能返回 | 300 秒 |
| `downloadUrl` | 关联可解析且可见，`usable` 或更高角色，同时具备 `products:read` 和 `products:download` | 300 秒 |

所有服务签发链接还受 API key 的到期时间限制。链接过期后重新获取商品数据，不要将签名 URL 当作素材 ID 保存。

<details id="product-media-fields">
<summary>封面、图片和关联素材返回哪些字段？</summary>

`cover` 是一个媒体对象，无封面时为 null；`images`、`relatedAssets` 为媒体对象数组。自定义图片/文件值可为数组或 null，未填写的字段可能省略。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | 整数或 null | 素材查询返回的 ID（FilePath ID），不是 AssetObject ID 或商品素材关联 ID |
| `name`、`mimeType` | 字符串或 null | 文件名、MIME 类型 |
| `size` | 字符串或 null | 十进制字节数，如 `"2048"`，不是 JSON 数字 |
| `width`、`height`、`duration` | 数字或 null | 媒体尺寸和时长 |
| `previewUrl` | URL 或 null | 用于展示的预览地址；不可用时为 null |
| `downloadUrl` | URL 或 null，可省略 | 原文件地址；返回条件见上表 |
| `downloadUrlExpiresAt` | 时间字符串或 null，可省略 | 下载地址的到期时间，RFC 3339 格式 |

</details>

<details>
<summary>链接缺失、旧版媒体和外部预览如何处理？</summary>

- 非图片素材只返回派生预览，原始 PDF、压缩包和文档不会作为预览回退。素材库素材查询和模板配置只包含预览。
- 缺少下载权限或关联无法解析时，会省略 `downloadUrl` 和 `downloadUrlExpiresAt`；已授权但原文件不可用时，这些值可能为 null。
- 已存储的外部 DAM 缩略图或预览，只对未设置过期时间的 API key 返回，并先排除已知原文件 URL。它们的有效期由第三方控制，不保证短有效期，也不保证校验提供方签名。
- API key 设置了 `expiresAt` 时，过期时间无法验证的外部预览返回 null。查询参数中形似签名的值不能作为可信的过期依据。
- 服务签发的链接仍遵守上表限制；签名失败时不会返回原始存储 URL。

### 获取或同步商品列表

**接口路径**： https://open.musedam.cc/api/muse/product-api

**请求方式**： POST

**接口描述**：普通分页按 updatedAt/id 降序排序。sync: "true" 时按 (updatedAt,id) 升序排序，使用包含的下界和不包含的固定上界（PostgreSQL 时钟减 30 秒）。全量扫描时省略 updatedAfter；请持续跟随每个 nextCursor，即使 data 页为空。游标绑定 key/角色/商品库/筛选条件/pageSize/边界。仅在遍历完毕后原样保存 syncedUntil；按 id 和 updatedAt 进行重放/去重。持续时间超过 30 秒安全窗口的事务属于 v1 已接受的限制。见[同步说明](#cycle-protocol)。view_only/usable 仅可见已发布商品。

所需角色：所有协作者角色。

**请求参数**：

### 创建草稿商品

**接口路径**： https://open.musedam.cc/api/muse/product-api

**请求方式**： POST

**接口描述**：仅创建草稿。创建时解析并固定一个模板版本；模板字段依据该不可变定义进行校验。可关联同一商品库中现有的 FilePath ID；不支持上传、远程导入或回写到提供方。

所需角色：editable 或 manage。

**请求参数**：

以下业务字段与 `service` 同级，直接放入 JSON 请求体，不要使用 `params` 或 `data` 包装。

| 参数名 | 类型 | 必填 | 描述 |
| - | - | - | - |
| service | String | 是 | 服务标识，固定为 `createProduct`. |

**ProductCreate参数说明**：

始终创建草稿。显式指定的 templateId 必须是同一商品库中的有效模板，且优先使用。当 templateId 省略且提供了 categoryId 时，解析顺序为：分类或其祖先分类的绑定，然后是该分类所属品牌的绑定，最后是商品库默认模板。当 categoryId 省略时，即使提供了 brandId，也仅考虑商品库默认模板。若未解析出任何模板，则商品没有模板。分类必须与最终品牌匹配；owner 必须是同一团队成员，默认为 null，而非 key 创建者。cover/images/related/自定义媒体合计最多 100 个引用。图片槽位要求使用图片；自定义媒体必须满足固定版本的数量/大小/类型限制。

不接受未定义字段。

| description | String | 否 | — |

| categoryId | Integer | 否 | 正整数 ID，最大 2147483647。 |
| ownerUserId | Integer | 否 | 正整数 ID，最大 2147483647。 |
| templateId | String | 否 | 最短 1 个字符；最长 128 个字符 |
| templateFields | Object | 否 | 按稳定的自定义字段 ID 浅合并；省略的值保持不变。未知/系统 ID 会被拒绝。即使是草稿也会校验类型/选项。image/file 的值为 FilePath ID 数组，而非 URL/对象快照。富文本内部可包含 null。`updateProduct` 依据固定版本进行校验，即使其有效模板已被删除。 |

## 下载记录

<details id="download-usage">
<summary>记录说明</summary>

下载历史包含团队内浏览器、成员、分享及既有 API Key 操作的记录。`requested` 表示操作已接受，不代表文件已传输或保存。商品读取、预览和直接访问签名 `downloadUrl` 不会创建下载记录。公开商品 API 不提供文件下载或导出操作；浏览器、成员和分享的下载及导出功能不变。

</details>

<summary>下载记录中的文件快照有哪些字段？</summary>

| `productId` | 正整数 | 所属商品 ID |

</details>
