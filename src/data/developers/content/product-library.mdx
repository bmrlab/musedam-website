## 快速接入

商品库全部 28 个操作统一使用 POST `https://open.musedam.cc/api/muse/product-api`。通过 `service` 指定下文的操作标识，所有业务参数放在扁平 JSON 请求体中。

1. 获取 MuseDAM API Key。
2. 请商品库管理员在「成员设置 → 添加成员」中，将该密钥添加为 API Key 协作者，并分配所需角色。
3. 从服务端调用接口，在请求头中携带 `Authorization: Bearer <APIKEY>`。

权限按密钥在 “成员设置” - “角色与权限” 中的设置

新添加的协作者默认为 `view_only`。按需要选择角色：

| 角色 | 可执行的操作 |
| --- | --- |
| `view_only` | 查看已发布商品，以及读取品牌、分类和信息模板。 |
| `usable` | 查看和分享已发布商品，获取商品媒体的签名下载链接（`downloadUrl`）。 |
| `editable` | 创建和编辑商品、访问草稿、发布及删除商品，以及查询商品库素材（`listAssets` / `getAsset`）。 |
| `manage` | 管理全部资源，包括品牌、分类、信息模板、团队分享记录及下载记录。 |

每个角色包含上一级角色的权限。后续示例中的资源 ID 需替换为实际值。

将 `your_api_key` 替换为已授权的 API Key，查询商品列表：

```bash
curl --request POST 'https://open.musedam.cc/api/muse/product-api' \
  --header 'Authorization: Bearer your_api_key' \
  --header 'Content-Type: application/json' \
  --data-raw '{
  "service": "listProducts",
  "page": 1,
  "pageSize": 20
}'
```

成功响应使用 HTTP 200，JSON 中 `code` 为 `"0"`，`message` 示例为 `"OK"`，`result.success` 为 `true`，商品数据位于 `result.data`，分页信息位于 `result.pagination`。`message` 文案不稳定，不要据此判断成功与否。列表为空时，先确认商品库中是否有当前角色可见的商品；`view_only` 和 `usable` 只能查看已发布商品。

## 请求与响应

所有接口统一使用 `POST https://open.musedam.cc/api/muse/product-api`，请求头携带 `Authorization: Bearer <APIKEY>` 和 `Content-Type: application/json`。`service` 与所有业务参数平铺在 JSON 请求体顶层。

**成功响应示例**：

```json
{
  "code": "0",
  "message": "OK",
  "result": {
    "success": true,
    "data": {},
    "code": null,
    "message": null,
    "requestId": "request_123"
  },
  "traceId": "trace_123"
}
```

已观察到的公网网关成功及错误响应均使用 HTTP 200。上游商品库失败时，外层 `code` 为 `"MB100005"`、`result` 为 `null`；无效凭证时为 `"MO100002"`、`result` 为 `null`。`message` 可能嵌入内部 HTTP 状态及响应正文，但仅供诊断，不是稳定的机器可解析协议。请保留响应 `traceId`；上游可能替换提交的 `traceId`。不保证透传 `Retry-After` 或 `X-Request-Id` 响应头。

**权限不足的网关失败响应示例（HTTP 200，诊断文案仅为示意）**：

```json
{
  "code": "MB100005",
  "message": "product-library HTTP 403: {\"code\":\"0\",\"result\":{\"success\":false,\"data\":null,\"code\":\"forbidden\",\"message\":\"Insufficient permissions\",\"requestId\":\"request_123\"}}",
  "result": null,
  "traceId": "trace_123"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | String | 公网网关码：成功为 `"0"`，上游失败为 `"MB100005"`，无效凭证为 `"MO100002"`。 |
| `message` | String | 成功示例为 `"OK"`；文案不稳定，仅供诊断，不应解析或用于分支判断。 |
| `result` | Object / null | 成功时包含业务结果；网关错误时为 `null`。 |
| `result.success` | Boolean | 公网成功结果中为 `true`；网关错误时没有此字段。 |
| `result.data` | Object / Array | 成功时根据接口返回对象或数组。 |
| `result.code` | null | 成功时为 `null`；内部错误码见[排障参考](#error-catalog)，不是公网错误结果字段。 |
| `result.message` | null | 成功时为 `null`；网关错误时没有此字段。 |
| `result.pagination` | Object | 列表与同步接口成功时返回的分页信息。 |
| `result.requestId` | String | 请求 ID。 |
| `traceId` | String | 链路追踪 ID。 |

普通列表接口支持 `page`（默认 `1`）和 `pageSize`（默认 `20`，最大 `100`），在 `result.pagination` 中返回分页统计。需要持续增量同步商品时，请使用[游标同步](#cycle-protocol)。

```json
{
  "page": 1,
  "pageSize": 20,
  "totalCount": 42,
  "totalPages": 3
}
```

<details id="error-catalog">
<summary>请求限制与内部错误码（排障参考）</summary>

下表及后续操作说明中的 401、403、404、409、413、422、500、503 均指商品库内部状态与 `result.code`，仅供排障，不是公网 HTTP 状态或网关错误结构。公网错误契约见上文，不要解析 `message` 中嵌入的内部响应。

请求体上限为 1 MiB。写入接口、历史记录接口和游标同步接口拒绝未知字段；普通列表和详情读取接口忽略未知字段（但请求体顶层属性值仍须为字符串、数字或布尔值）。

| HTTP 状态码 | `result.code` | 说明与处理方式 |
| --- | --- | --- |
| 401 | `invalid_credentials` | API Key 无效或缺失，检查 `Authorization: Bearer` 请求头。 |
| 401 | `key_inactive` | API Key 已停用或已过期。 |
| 403 | `forbidden` | 当前协作者角色权限不足，或资源不可见。 |
| 404 | `not_found` | 资源不存在、已删除或当前角色不可访问。 |
| 409 | `sku_in_use` | 商品 `spu` 已被占用（含已删除商品）。 |
| 409 | `code_in_use` | 资源编码冲突，请重试或更换编码。 |
| 409 | `name_in_use` | 同级分类名称或模板名称已存在。 |
| 409 | `brand_has_dependents` | 品牌下仍有有效分类或商品，需先移除或迁移。 |
| 409 | `category_has_products` | 分类子树下仍有有效商品，需先移除或迁移。 |
| 409 | `default_template_replacement_required` | 删除商品库默认模板时，未通过 `replacementForLibraryDefault` 指定替代模板 ID（该字段不接受 `null`）。 |
| 409 | `mutation_response_unavailable` | 变更已提交（`result.mutationOutcome: "committed"`），但无法返回结果；请先查询核对状态，切勿重复提交。 |
| 413 | `payload_too_large` | 请求体超过 1 MiB 上限。 |
| 422 | `validation_failed` | 参数校验失败，根据 `result.message` 中的字段详情修正输入。 |
| 503 | `authentication_unavailable` | 鉴权服务暂时不可用，请稍后重试。 |
| 503 | `write_conflict` | 写入锁冲突已回滚，等待后重试；公网不保证透传 `Retry-After`。 |
| 500 | `internal_server_error` | 服务端异常，请保留 `traceId` 与 `result.requestId` 排查，重试写入前先核对状态。 |

</details>

## 分类

<details id="category-rules">
<summary>分类树与删除</summary>

同级名称必须唯一，父分类必须属于同一品牌。分类最多 10 级，每个品牌最多 5000 个未删除节点。`sortOrder` 是从零开始的同级位置；创建或移动时省略则追加，同父级更新时省略则保持位置。改名或移动会更新后代路径。

创建时，只有商品库默认模板未绑定品牌或已绑定当前品牌，才添加直接模板绑定；否则仍创建成功，按祖先分类、品牌、商品库默认模板查找。删除会软删除整棵子树；其中有未删除商品时返回 `409 category_has_products`，不执行删除。

</details>

## 信息模板

<details id="template-groups">
<summary>分组 groups</summary>

`groups` 包含 1–200 个分组，一个模板的字段总数最多为 200。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 现有分组必填，1–128 个字符，必须属于本模板；新分组不传。 |
| `name` | string | 必填，1–128 个字符，去除首尾空白。 |
| `fields` | array | 必填，分组中的字段，见[字段说明](#template-fields)。 |

现有分组保持原有顺序，新分组按提交顺序追加。分组不接受 `sortOrder` 或 `isDefault`。默认分组由服务器指定，不能删除。

</details>

<details id="template-fields">
<summary>字段 fields</summary>

新字段必须提供 `key`、`name` 和 `type`。更新现有字段时必须传 `id`。类型不变时，省略的属性保留原值，`sortOrder` 除外；改变 `type` 时，`config` 会按目标类型迁移，必要时须显式提供新配置。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 现有字段必填，1–128 个字符，必须属于当前分组；新字段不传。 |
| `key` | string | 新字段必填，1–64 个字符，须以英文字母或下划线开头且仅含英文字母、数字和下划线（`^[a-zA-Z_][a-zA-Z0-9_]*$`），在同一模板内唯一；已有字段不可修改。 |
| `name` | string | 新字段必填，1–128 个字符。 |
| `type` | string | 新字段必填，支持的类型见[字段配置](#field-configuration)。 |
| `required` | boolean | 可选；新字段默认为 `false`。 |
| `placeholder` | string | 可选，最多 255 个字符（不接受 `null`）；更新时省略以保留原值，新字段响应默认为 `null`。 |
| `sortOrder` | integer | 可选，同组内唯一的非负整数；省略时使用字段在数组中的位置。 |
| `config` | object | 按字段类型填写，见[字段配置](#field-configuration)；新字段省略时使用 `{}`，但仍须满足该类型的配置要求。 |
| `typeChangeConfirmed` | boolean | 可选；允许但需要确认的类型变更须传 `true`。 |

创建时会自动加入名称（`name`）、SKU（`sku`）和主图（`mainImage`）三个受保护系统字段，因此最多可新增 197 个自定义字段。第一个分组的自定义字段排列在这三个字段之后，传入的 `sortOrder`（省略时为数组位置）会增加 3。更新模板传入 `groups` 时，须保留已有系统字段的 `id`、`type`、`required` 和 `config`（仅允许修改系统字段的 `name`、`placeholder` 和排序位置）。字段不能移到其他分组。

新字段只能是自定义字段，不能使用保留的系统 key。`isSystemField` 和 `systemKey` 不能用于创建或重新分配系统身份；更新时保留原有身份。若提供 `systemKey`，必须是字符串：`name`、`sku`、`brand`、`category`、`description` 或 `mainImage`；自定义字段应省略该属性（请勿传入 `null`）。未知的分组或字段属性会被拒绝。

</details>

<details id="field-configuration">
<summary>字段配置 config</summary>

配置由字段的 `type` 决定。例如，文本字段使用 `{}`，货币和选项字段需要额外配置。

| 字段类型 | config 配置 |
| --- | --- |
| `text`、`textarea`、`email`、`phone`、`url`、`color`、`date`、`dateRange` | 使用 `{}`，不接受其他配置。 |
| `number` | 可选 `unit`，字符串。 |
| `currency` | 必填 `code`、`symbol`（非空字符串）和 `decimals`（0–4 的整数）。 |
| `richtext` | 必填 `mode`，取值为 `html` 或 `delta`。 |
| `select`、`radio`、`checkbox` | 必填非空 `options` 数组。每项见下表，`value` 不得重复。 |
| `image`、`file` | 可选 `maxCount`（大于等于 1 的整数）、`maxSizeMB`（大于 0 的数字）和 `accept`（字符串数组）。 |

每个 `options` 元素包含：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `value` | string | 必填，非空，选项的唯一值。 |
| `label` | string | 必填，非空，显示名称。 |
| `sortOrder` | integer | 必填，非负整数。 |
| `archived` | boolean | 可选，是否归档该选项。 |

通过 API 更新模板时，所有系统字段（`isSystemField: true`）的 `type`、`required` 和 `config` 均不可修改，传入时须与原模板保持一致（或省略以保留原值）。

空配置和系统字段配置拒绝未知属性；其他配置及选项会移除未知属性。完整机器可读定义可下载 [OpenAPI JSON](/assets/developers/product-library/openapi.json)。

</details>

<details id="template-definition">
<summary>返回的模板定义</summary>

模板详情的 `groups` 和商品的 `templateDefinition.groups` 均包含分组与字段。商品返回的是创建时固定的版本，后续模板修改或删除不会改变它；未绑定模板时，`templateDefinition` 可为 `null`。

分组固定返回 `id`、`name`、`fields`，以及以下只读属性：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `isDefault` | boolean | 是否为默认分组。 |
| `sortOrder` | integer | 分组顺序。 |

每个字段固定返回 `id`、`key`、`name`、`type`、`required`、`placeholder`、`sortOrder`、`config`，以及以下属性；不返回写入参数 `typeChangeConfirmed`。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `isSystemField` | boolean | 是否为系统字段。 |
| `systemKey` | string 或 null | 系统身份：`name`、`sku`、`brand`、`category`、`description`、`mainImage`；自定义字段为 `null`。 |

`placeholder` 可为 `null`。配置中的媒体引用会返回安全的预览信息，不包含存储路径或凭据。所有协作者角色在读取商品详情时均可获取该固定模板定义。

</details>

<details id="fields-Template">
<summary>Template 返回字段</summary>

| 字段名 | 类型 | 描述 |
| - | - | - |
| id | String | 模板 ID，最短 1 个字符；最长 128 个字符。 |
| name | String | 名称。 |
| description | String | 说明。可为 null |
| enabled | Boolean | 是否启用模板。 |
| isSystemDefault | Boolean | 是否为系统默认模板。 |
| isLibraryDefault | Boolean | 是否为商品库默认模板。 |
| createdAt | String | RFC 3339 时间字符串；保留完整精度。|
| updatedAt | String | RFC 3339 时间字符串；保留完整精度。|
| boundBrandIds | List&lt;Integer&gt; | 绑定的品牌 ID。每个元素为正整数 ID（最大 2147483647）。 |
| boundCategoryIds | List&lt;Integer&gt; | 绑定的分类 ID。每个元素为正整数 ID（最大 2147483647）。 |
| groups | List&lt;VersionGroup&gt; | 模板分组。嵌套字段：[模板分组与字段](#template-definition) |

</details>

<details id="template-pins-and-field-values">
<summary>模板版本与自定义字段</summary>

商品创建时保存模板版本。读取 `templateDefinition` 解释 `templateFields`；后续模板变更或删除不影响这个版本，`updateProduct` 不能更换模板。`templateFields` 以固定版本中的自定义字段 `id` 为键（不支持传入系统字段 ID 或字段 `key`），更新时浅合并；省略的字段保持不变。

显式传入的 `templateId` 优先；省略 `templateId` 且传入 `categoryId` 时，依次查找该分类、其祖先分类、所属品牌绑定的模板以及商品库默认模板；未传 `categoryId` 时（即使传入了 `brandId`），仅使用商品库默认模板。

<details id="cycle-protocol">
<summary>同步与检查点</summary>

1. 首次使用 `"sync": "true"`，省略 `updatedAfter`；增量周期传入上次完成的 `result.pagination.syncedUntil`。
2. 按商品 `id` 和 `updatedAt` 合并，保留较新版本。
3. 使用 `"sync": "true", "cursor": "<nextCursor>"` 跟随 `result.pagination.nextCursor` 直到 null；即使 `result.data` 为空，也要继续。
4. 完成后原样保存 `result.pagination.syncedUntil`，不要改用最后一条商品的时间。

游标绑定密钥、角色、商品库、筛选条件和页大小；续页时不要改变它们。更换授权或筛选条件要开始新周期；范围扩大时重新全量同步。检查点和同步 `updatedAt` 保留完整六位小数，不要用 JavaScript Date 截断精度。每周期读取当前状态的 `[updatedAfter, syncedUntil)`，上界为首次请求时服务端时间减 30 秒；长事务仍可能影响完整性，不提供每次变更的事件流。


同步请求在 `result.data` 中返回商品列表，在 `result.pagination` 中返回同步元数据：`pageSize`、`syncedUntil`、`nextCursor` 和 `hasMore`。续页时将返回的 `result.pagination.nextCursor` 原样填入下一次请求的 `cursor` 字段，不要重命名请求字段或使用 `result` 包装业务参数。

</details>

<details id="reconciling-removals">
<summary>清理已删除或不可见的商品</summary>

同步不会返回删除事件。定期将本地商品 ID 交给[核对已知商品 ID](#operation-checkProductVisibility) 接口，返回 `not_visible` 时移除本地副本。该接口不检查品牌、分类或搜索等业务筛选；若只维护筛选后的副本，须定期全量核对筛选结果，或同步全部可见商品后在本地筛选。

</details>

<details id="media-and-expiry">
<summary>预览与下载链接</summary>

展示商品媒体时使用 `previewUrl`。需要原文件时，检查 `downloadUrl`；能预览不等于有下载权限。

| 链接 | 返回条件 | 服务签发链接的有效期上限 |
| --- | --- | --- |
| 派生预览 | 具备商品或素材查看权限 | 3600 秒 |
| 图片原图预览回退 | 仅适用于图片，`view_only` 也可能返回 | 300 秒 |
| `downloadUrl` | 关联素材可解析且可见，且当前角色为 `usable`、`editable` 或 `manage` | 300 秒 |

所有服务签发链接还受 API Key 的到期时间限制。链接过期后请重新获取商品数据，不要将签名 URL 当作素材 ID 保存。

- 非图片素材只返回派生预览，原始 PDF、压缩包和文档不会作为预览回退。素材查询接口（`listAssets` / `getAsset`）和模板配置中的媒体仅返回预览链接。
- 当前角色无下载权限（如 `view_only`）或关联无法解析时，响应会省略 `downloadUrl` 和 `downloadUrlExpiresAt`；具备下载权限但原文件不可用时，这些字段值为 `null`。
- 已存储的外部 DAM 缩略图或预览，仅对未设置过期时间的 API Key 返回（并排除已知原文件 URL），其有效期由外部存储服务控制。若 API Key 设置了到期时间，过期时间无法验证的外部预览会返回 `null`。
- 签名失败时不会返回原始存储地址。

</details>

### 获取或同步商品列表

**接口路径**： https://open.musedam.cc/api/muse/product-api

**请求方式**： POST

**接口描述**：支持普通分页与游标增量同步两种模式。普通分页按 `(updatedAt, id)` 降序排序；当 `sync: "true"` 时按 `(updatedAt, id)` 升序排序，并在左闭右开时间窗口 `[updatedAfter, syncedUntil)` 内扫描（上界 `syncedUntil` 固定为首次请求时的服务端时间减 30 秒）。全量同步时省略 `updatedAfter`；请持续跟随每个 `nextCursor` 直至为 `null`（即使某页 `result.data` 为空）。仅在遍历结束后原样保存 `syncedUntil`，并按 `id` 和 `updatedAt` 合并去重。详见[同步与检查点](#cycle-protocol)。`view_only` 和 `usable` 角色仅可见已发布商品。

所需角色：所有协作者角色。

**请求参数**：

以下业务字段与 `service` 同级，直接放入 JSON 请求体，不要使用 `params` 或 `data` 包装。

| 参数名 | 类型 | 必填 | 描述 |
| - | - | - | - |
| service | String | 是 | 服务标识，固定为 `listProducts`。 |
| page | Integer | 否 | 页码，正整数，默认 1；`sync: "true"` 时不可用。 |
| pageSize | Integer | 否 | 每页条数，正整数，默认 20，上限 100。 |
| search | String | 否 | 去除首尾空白、不区分大小写的子串匹配：匹配商品 `name` 或 `spu`。 |
| brandId | Integer | 否 | 按本商品库内的品牌 ID 筛选。正整数 ID（最大 2147483647）。 |
| categoryId | Integer | 否 | 按精确的分类 ID 筛选，不包含其子分类。正整数 ID（最大 2147483647）。 |
| status | String | 否 | 按商品状态筛选（不会扩大当前角色的可见范围）。允许值：draft、published |
| sync | String | 否 | `"true"` 表示开启游标增量同步；`"false"` 表示普通分页。见[同步与检查点](#cycle-protocol)。允许值：true、false；默认值："false" |
| updatedAfter | String | 否 | 仅在 `sync: "true"` 时使用。包含的下界（RFC 3339 格式，支持 `Z` 或时区偏移，0–6 位小数）。增量同步时请直接传入上一轮保存的 `syncedUntil` 字符串；全量同步时省略。 |
| cursor | String | 否 | 续页游标令牌，仅在 `sync: "true"` 时使用（见[同步与检查点](#cycle-protocol)）。游标已绑定 API Key、角色、商品库、时间边界、筛选条件和 `pageSize`；续页时可省略其他业务参数，或重复传入完全一致的值。最短 1 个字符；最长 8,192 个字符 |

**响应参数**： `200`，`result.data`：List&lt;ProductSummary&gt;。 [字段说明](#fields-ProductSummary) 分页字段见[请求与响应](#wire-format-and-identifiers)。

**同步分页字段（`result.pagination`）**：

| 字段名 | 类型 | 描述 |
| - | - | - |
| pageSize | Integer | 每页数量。最小值：1；最大值：100 |
| syncedUntil | String | 本轮同步窗口的上界（服务端时间减 30 秒，在整个同步周期内固定不变）。仅在 `nextCursor` 为 `null` 后原样保存此字符串，作为下一轮的 `updatedAfter`。格式：date-time；须匹配 `^\d{4}-\d\d-\d\dT\d\d:\d\d:\d\d\.\d{6}Z$` |
| nextCursor | String | 下一页游标，本轮扫描结束后为 `null`。最长 8,192 个字符；可为 null |
| hasMore | Boolean | 是否还有下一页同步数据。 |

请求示例：

```bash
  --header 'Authorization: Bearer your_api_key' \
  --header 'Content-Type: application/json' \
  --data-raw '{
  "service": "listProducts",
  "page": 1,
  "pageSize": 20
}'
```

### 创建草稿商品

**接口路径**： https://open.musedam.cc/api/muse/product-api

**请求方式**： POST

**接口描述**：创建草稿商品（如需发布，请在创建后调用 `setProductStatus`）。创建时会解析并固定一个信息模板版本；自定义字段依据该不可变版本定义进行校验。可关联当前商品库中已有的素材 ID（通过 `listAssets` / `getAsset` 获取）；本接口不支持直接上传文件。

所需角色：editable 或 manage。

**请求参数**：

以下业务字段与 `service` 同级，直接放入 JSON 请求体，不要使用 `params` 或 `data` 包装。显式指定的 `templateId` 必须是当前商品库中的有效模板，且优先使用。当 `templateId` 省略且提供了 `categoryId` 时，解析顺序为：分类或其祖先分类的绑定模板 → 该分类所属品牌的绑定模板 → 商品库默认模板。当 `categoryId` 省略时（即使提供了 `brandId`），仅考虑商品库默认模板。若未解析出任何模板，则商品无绑定模板。分类必须属于所选品牌；`ownerUserId` 必须是同一团队成员，省略时默认为 `null`。封面、商品图片、关联素材及自定义媒体字段合计最多引用 100 个素材。图片槽位要求素材为图片类型；自定义媒体字段须满足模板版本的数量、大小和格式限制。

### 获取商品及其固定版本定义

**接口路径**： https://open.musedam.cc/api/muse/product-api

**请求方式**： POST

**接口描述**：返回可访问的有效商品及其固定的不可变模板定义（即使原模板已变更或被删除）。每次响应都会生成媒体预览链接；当角色为 `usable`、`editable` 或 `manage` 时，还会返回原文件下载签名链接（`downloadUrl`）。草稿商品对 `view_only` 和 `usable` 角色不可见。

所需角色：所有协作者角色。

**请求参数**：

以下业务字段与 `service` 同级，直接放入 JSON 请求体，不要使用 `params` 或 `data` 包装。

| 参数名 | 类型 | 必填 | 描述 |
| - | - | - | - |
