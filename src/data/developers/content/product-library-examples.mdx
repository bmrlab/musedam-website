下面的示例可分别使用。将 `your_api_key` 替换为你的 API Key，将示例资源 ID 替换为当前商品库中的实际 ID。

## 查询商品列表

密钥需要先添加为 API Key 协作者，详见[获取授权](./product-library#authentication-and-scope)。以下请求返回当前角色可见的商品列表。

```bash
curl --request GET 'https://open.musedam.cc/api/product/products?page=1&pageSize=20' \
  --header 'Authorization: Bearer your_api_key'
```

读取响应中的 `data` 获取商品，读取 `pagination` 获取分页信息。`view_only` 和 `usable` 角色只能查看已发布商品。

## 创建品牌、分类和模板

创建品牌需要 `manage` 角色。

```bash
curl --request POST 'https://open.musedam.cc/api/product/brands' \
  --header 'Authorization: Bearer your_api_key' \
  --header 'Content-Type: application/json' \
  --data-raw '{"name":"Example brand"}'
```

响应中的 `data.id` 是品牌 ID。分类和模板的创建参数见[商品分类](./product-library-categories)与[商品信息模板](./product-library-template-writes)，无需为了调用商品接口重新创建已有资源。

## 查找素材

创建或编辑商品前，可以查找已有图片素材。此接口需要 `editable` 或 `manage` 角色。

```bash
curl --request GET 'https://open.musedam.cc/api/product/assets?mimeType=image%2F&pageSize=20' \
  --header 'Authorization: Bearer your_api_key'
```

将响应中的素材 `id` 用作商品的 `coverAssetId` 或 `imageAssetIds`。返回的 `previewUrl` 用于预览。

## 创建商品

创建商品需要 `editable` 或 `manage` 角色。以下示例使用品牌 `10`、该品牌下的分类 `20` 和图片素材 `30`，请替换为已有资源 ID。

```bash
curl --request POST 'https://open.musedam.cc/api/product/products' \
  --header 'Authorization: Bearer your_api_key' \
  --header 'Content-Type: application/json' \
  --header 'Idempotency-Key: create-product-001' \
  --data-raw '{"name":"Example product","spu":"EXAMPLE-001","brandId":10,"categoryId":20,"coverAssetId":30,"imageAssetIds":[30]}'
```

新商品为草稿，商品 ID 位于 `data.id`。同一次创建失败后重试时，保持请求体和 `Idempotency-Key` 不变；创建另一个商品时使用新的幂等键。

## 更新与发布商品

更新商品 `40` 的描述：

```bash
curl --request PATCH 'https://open.musedam.cc/api/product/products/40' \
  --header 'Authorization: Bearer your_api_key' \
  --header 'Content-Type: application/json' \
  --data-raw '{"description":"New product description"}'
```

省略的字段保持原值。允许为空的字段可传 `null` 清空，媒体列表可传 `[]` 清空。需要防止覆盖并发修改时，可通过 `If-Match` 传入读取时返回的 `ETag`，详见[写入与错误处理](./product-library-write-conventions)。

发布商品 `40`：

```bash
curl --request PATCH 'https://open.musedam.cc/api/product/products/40/status' \
  --header 'Authorization: Bearer your_api_key' \
  --header 'Content-Type: application/json' \
  --data-raw '{"status":"published"}'
```

发布前需填写模板要求的必填字段，并确保素材有效。校验失败时返回 `422` 和字段详情，商品保持原状态。

## 读取商品与预览

获取商品 `40` 的详情：

```bash
curl --request GET 'https://open.musedam.cc/api/product/products/40' \
  --header 'Authorization: Bearer your_api_key'
```

使用商品媒体中的 `previewUrl` 展示预览。具备下载权限时，媒体还可能包含 `downloadUrl` 和 `downloadUrlExpiresAt`。链接过期后重新读取商品即可。

## 分享、导出和下载

为已发布商品 `40` 创建一个有效期为 7 天、不可下载的分享，需要 `usable` 及以上角色：

```bash
curl --request POST 'https://open.musedam.cc/api/product/product-shares' \
  --header 'Authorization: Bearer your_api_key' \
  --header 'Content-Type: application/json' \
  --data-raw '{"productIds":[40],"expiresInDays":7,"allowDownload":false}'
```

响应中的 `data.url` 是分享链接。

将商品 `40` 导出为 Excel，需要 `usable` 及以上角色：

```bash
curl --request POST 'https://open.musedam.cc/api/product/product-downloads' \
  --header 'Authorization: Bearer your_api_key' \
  --header 'Content-Type: application/json' \
  --data-raw '{"kind":"export","productIds":[40],"format":"xlsx","includeAssetUrls":false}' \
  --output 'products.xlsx'
```

示例将结果保存为 `products.xlsx`，不包含素材链接。`format` 也支持 `csv` 和 `json`。

下载商品 `40` 的原文件，需要 `usable` 及以上角色：

```bash
curl --request POST 'https://open.musedam.cc/api/product/product-downloads' \
  --header 'Authorization: Bearer your_api_key' \
  --header 'Content-Type: application/json' \
  --data-raw '{"kind":"assets","productIds":[40]}' \
  --output 'product-download'
```

结果保存为 `product-download`。只有一个文件时返回原文件，多个文件时返回 ZIP，可按实际文件类型修改保存名称。

## 了解商品的模板版本

商品创建时会保存所用模板的版本。后续修改或删除模板，不会改变已有商品的字段定义。通过商品详情中的 `templateDefinition` 读取该版本，详见[商品信息模板](./product-library-template-writes)。

## 同步商品

首次同步从以下请求开始：

```bash
curl --request GET 'https://open.musedam.cc/api/product/products?sync=true&pageSize=100' \
  --header 'Authorization: Bearer your_api_key'
```

如果 `pagination.nextCursor` 不为 `null`，将其完整值替换下面的 `your_cursor`，继续读取下一页：

```bash
curl --get 'https://open.musedam.cc/api/product/products' \
  --header 'Authorization: Bearer your_api_key' \
  --data-urlencode 'sync=true' \
  --data-urlencode 'cursor=your_cursor'
```

继续使用每次返回的 `nextCursor`，直到其为 `null`，即使某一页的 `data` 为空也应继续。所有页面处理完成后，原样保存 `pagination.syncedUntil`；下次同步在首请求中将它作为 `updatedAfter` 传入。时间戳需保留完整精度，完整规则见[商品同步](./product-library-synchronization)。

## 核对商品可见性

同步不会返回已删除商品的记录。定期检查本地保存的商品 ID：

```bash
curl --request POST 'https://open.musedam.cc/api/product/products/visibility' \
  --header 'Authorization: Bearer your_api_key' \
  --header 'Content-Type: application/json' \
  --data-raw '{"ids":[40,41]}'
```

响应为 `not_visible` 的商品应从本地副本移除。该状态也可能表示草稿不可见或无访问权限，不应据此推断商品是否存在。如需删除商品本身，参见[商品操作指南](./product-library-product-writes)。

## 处理常见错误

| 状态码 | 处理方式 |
| --- | --- |
| 401 / 403 | 检查 API Key 状态与协作者角色。 |
| 412 | 重新读取商品，核对变更后使用新的 ETag 重试。 |
| 422 | 检查请求参数；若响应含 `details`，按 `details[].field` 和 `details[].message` 修正。 |
| 409 | 根据 `code` 处理冲突；若为 `mutation_response_unavailable`，先读取并核对结果。 |

保留响应中的 `requestId` 便于排查。完整说明见[错误码](./product-library-write-conventions#error-catalog)。
