所有路徑均使用 `/api/product`。寫入需要 `manage` API Key 協作者權限。

## 建立與更新

建立模板時，提供名稱和至少一個分組。以下範例新增一個選填的顏色欄位：

```json
{
  "name": "Catalog",
  "groups": [
    {
      "name": "Basics",
      "fields": [
        { "key": "color", "name": "Color", "type": "text" }
      ]
    }
  ]
}
```

`POST /product-info-templates` 回傳 `201`；`PATCH /product-info-templates/{id}` 回傳 `200`。兩者均回傳模板詳情和 `ETag`。名稱為 1–30 個字元，描述最多 50 個字元。

更新時，省略 `groups` 會保留原有定義；提供 `groups` 會替換完整定義。保留現有分組和欄位的 `id`，新分組和欄位不傳 `id`。省略的現有分組和欄位會被軟刪除。

<details>
<summary>綁定、預設模板和版本規則</summary>

- `boundBrandIds`、`boundCategoryIds` 只替換所提供維度的綁定，省略則保持不變，每個陣列最多 10,000 個 ID。ID 必須屬於同一商品庫；選定品牌時，分類必須屬於這些品牌。已綁定其他模板的 ID 會轉移到本模板。
- `isLibraryDefault: true` 將本模板設為商品庫預設模板；`false` 僅清除本模板的預設狀態，省略則保持不變。
- 每次成功建立或更新都會儲存一個新版本。只支援 `syncStrategy: "newOnly"`，`syncAll` 回傳 `422 validation_failed`。既有商品繼續使用建立時的模板版本，欄位定義和值不隨模板更新而變化。

</details>

`POST` 可透過 `Idempotency-Key` 安全重試，更新可透過 `If-Match` 檢查版本，詳見[寫入約定](./product-library-write-conventions)。完整頂層參數見[建立模板](./product-library-reference#operation-createTemplate)和[更新模板](./product-library-reference#operation-updateTemplate)。

## 分組 groups

`groups` 包含 1–200 個分組，一個模板的欄位總數最多為 200。

| 欄位 | 類型 | 說明 |
| --- | --- | --- |
| `id` | string | 現有分組必填，1–128 個字元，必須屬於本模板；新分組不傳。 |
| `name` | string | 必填，1–128 個字元，去除首尾空白。 |
| `fields` | array | 必填，分組中的欄位，見下表。 |

現有分組保持原有順序，新分組按提交順序附加。分組不接受 `sortOrder` 或 `isDefault`。預設分組由伺服器指定，不能刪除。

## 欄位 fields

新欄位必須提供 `key`、`name` 和 `type`。更新現有欄位時必須傳 `id`，省略的屬性保留原值，`sortOrder` 除外。

| 欄位 | 類型 | 說明 |
| --- | --- | --- |
| `id` | string | 現有欄位必填，1–128 個字元，必須屬於目前分組；新欄位不傳。 |
| `key` | string | 新欄位必填，1–64 個字元，須為唯一的有效識別符；既有欄位不能修改。 |
| `name` | string | 新欄位必填，1–128 個字元。 |
| `type` | string | 新欄位必填，支援的類型見下方設定表。 |
| `required` | boolean | 選填；新欄位預設為 `false`。 |
| `placeholder` | string 或 null | 選填，最多 255 個字元；新欄位預設為 `null`。 |
| `sortOrder` | integer | 選填，非負整數；省略時使用欄位在陣列中的位置。 |
| `config` | object | 按欄位類型填寫，見下方設定表；新欄位省略時使用 `{}`，但仍須滿足該類型的設定要求。 |
| `typeChangeConfirmed` | boolean | 選填；允許但需要確認的類型變更須傳 `true`。 |

<details>
<summary>系統欄位和更新限制</summary>

建立時會自動加入名稱、SKU 和主圖三個受保護欄位，因此最多可新增 197 個自訂欄位。替換定義時須保留這些欄位的 `id`，以及類型、必填標記和設定。欄位不能移到其他分組。

新欄位只能是自訂欄位，不能使用保留的系統 key。`isSystemField` 和 `systemKey` 不能用於建立或重新分配系統身分；更新時保留原值。未知的分組或欄位屬性會被拒絕。

</details>

## 欄位設定 config

設定由欄位的 `type` 決定。例如，文字欄位使用 `{}`，貨幣和選項欄位需要額外設定。

<details>
<summary>查看各欄位類型的設定</summary>

| 欄位類型 | config 設定 |
| --- | --- |
| `text`、`textarea`、`email`、`phone`、`url`、`color`、`date`、`dateRange` | 使用 `{}`，不接受其他設定。 |
| `number` | 選填 `unit`，字串。 |
| `currency` | 必填 `code`、`symbol`（非空字串）和 `decimals`（0–4 的整數）。 |
| `richtext` | 必填 `mode`，取值為 `html` 或 `delta`。 |
| `select`、`radio`、`checkbox` | 必填非空 `options` 陣列。每項見下表，`value` 不得重複。 |
| `image`、`file` | 選填 `maxCount`（大於等於 1 的整數）、`maxSizeMB`（大於 0 的數字）和 `accept`（字串陣列）。 |

每個 `options` 元素包含：

| 欄位 | 類型 | 說明 |
| --- | --- | --- |
| `value` | string | 必填，非空，選項的唯一值。 |
| `label` | string | 必填，非空，顯示名稱。 |
| `sortOrder` | integer | 必填，非負整數。 |
| `archived` | boolean | 選填，是否封存該選項。 |

系統欄位的可用設定是 `customPlaceholder`（選填字串，最多 255 個字元）；品牌、分類系統欄位不接受自訂選項。受保護系統欄位的設定不能變更。

空設定和系統設定拒絕未知屬性；其他設定及選項會移除未知屬性。完整機器可讀定義可下載 [OpenAPI JSON](/assets/developers/product-library/openapi.json)。

</details>

## 回傳的模板定義

模板詳情的 `groups` 和商品的 `templateDefinition.groups` 均包含分組與欄位。商品回傳的是建立時固定的版本，後續模板修改或刪除不會改變它；未綁定模板時，`templateDefinition` 可為 `null`。

<details>
<summary>查看分組與欄位的回傳屬性</summary>

分組固定回傳 `id`、`name`、`fields`，以及以下唯讀屬性：

| 欄位 | 類型 | 說明 |
| --- | --- | --- |
| `isDefault` | boolean | 是否為預設分組。 |
| `sortOrder` | integer | 分組順序。 |

每個欄位固定回傳 `id`、`key`、`name`、`type`、`required`、`placeholder`、`sortOrder`、`config`，以及以下屬性；不回傳寫入參數 `typeChangeConfirmed`。

| 欄位 | 類型 | 說明 |
| --- | --- | --- |
| `isSystemField` | boolean | 是否為系統欄位。 |
| `systemKey` | string 或 null | 系統身分：`name`、`sku`、`brand`、`category`、`description`、`mainImage`；自訂欄位為 `null`。 |

`placeholder` 可為 `null`。設定中的媒體引用會回傳安全的預覽資訊，不包含儲存路徑或憑證。讀取商品的固定模板定義不需要 `templates:read` 權限。

</details>

## 前置條件與刪除

`PATCH` 和 `DELETE` 接受選填的 `If-Match`。原樣傳入讀取模板時的 `ETag`；值過期時回傳 `412 precondition_failed`，模板保持不變。省略時，後一次寫入覆蓋前一次。

`DELETE /product-info-templates/{id}` 軟刪除模板並移除品牌、分類綁定，保留歷史版本和商品的固定版本。成功回傳 `200`，包含已刪除的 ID 和 `ETag`。

<details>
<summary>刪除預設模板與錯誤處理</summary>

刪除商品庫預設模板時，必須提供 JSON 欄位 `replacementForLibraryDefault`，值為同一商品庫中另一個未刪除模板的 ID，或用 `null` 清除預設模板。省略時回傳 `409 default_template_replacement_required`。刪除非預設模板無需請求本文。

無效定義、引用、受保護欄位變更或重複欄位 key 回傳 `422 validation_failed`；重複的未刪除模板名稱回傳 `409 name_in_use`；模板不存在或不屬於目前商品庫時回傳 `404 not_found`。

</details>
