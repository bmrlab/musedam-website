## 審批開放接口

- **生產環境基礎地址**：`https://open.musedam.cc/api/muse`
- **審批接口路徑**：`/approval-api`
- **完整調用地址**：`POST https://open.musedam.cc/api/muse/approval-api`
- **開通要求**：僅在購買並開通「審批中心擴展模組」後可使用。

## 調用約定

- 請求方法：`POST`
- `Content-Type`：`application/json`
- 請求體必須是合法 JSON
- 使用 `service` 區分具體能力
- 請求頭需攜帶：`Authorization: Bearer your_api_key`

可用 `service`：

- `subscriptionQuery`
- `subscriptionChange`
- `listTemplates`
- `createApproval`
- `taskStatusQuery`

## 統一響應

```json
{
  "code": "0",
  "message": "成功",
  "result": {},
  "traceId": "trace_xxx"
}
```

常見錯誤碼：

- `400`：參數錯誤
- `401`：鑑權失敗
- `403`：權限不足
- `404`：資源不存在
- `500`：服務內部錯誤

## listTemplates

**接口路徑**：`/approval-api`

**請求參數**：

| 字段名 | 類型 | 必填 | 描述 |
|-|-|-|-|
| service | String | 是 | 固定為 `listTemplates` |

**響應（result）**：模板陣列，單項字段如下：

| 字段名 | 類型 | 描述 |
|-|-|-|
| id | String | 模板 ID |
| name | String | 模板名稱 |
| description | String | 模板描述 |
| enabled | Boolean | 模板是否啟用 |
| usageCount | Number | 使用次數 |
| autoImportEnabled | Boolean | 是否自動入庫 |
| targetFolder | Object \| null | 入庫目標資料夾 |
| workflow | Array | 節點流程定義 |

請求示例：

```json
{
  "service": "listTemplates"
}
```

`result` 為模板陣列，常見字段：
`id`、`name`、`description`、`enabled`、`usageCount`、`autoImportEnabled`、`targetFolder`、`workflow`。

**curl 示例**：

```bash
curl --location --request POST 'https://open.musedam.cc/api/muse/approval-api' \
--header 'Authorization: Bearer your_api_key' \
--header 'Content-Type: application/json' \
--data-raw '{
    "service": "listTemplates"
}'
```

## createApproval

**接口路徑**：`/approval-api`

**請求參數**：

| 字段名 | 類型 | 必填 | 描述 |
|-|-|-|-|
| service | String | 是 | 固定為 `createApproval` |
| templateId | String | 是 | 審批模板 ID |
| createdBy | String | 是 | 發起人使用者 ID |
| assets | Array | 條件必填 | 與 `groups/groupList` 二選一；一般素材列表，至少 1 筆 |
| groups | Array | 條件必填 | 與頂層 `assets` 二選一；組合素材列表 |
| groupList | Array | 條件必填 | `groups` 的相容字段，與頂層 `assets` 二選一 |
| sourceContext | Object | 否 | 業務上下文 |
| reason | String | 否 | 發起原因 |

**assets[] 字段**：

| 字段名 | 類型 | 必填 | 描述 |
|-|-|-|-|
| name | String | 是 | 素材名稱，建議傳原始檔名 |
| url | String | 是 | 公網可訪問 `http/https` 地址 |
| size | Number | 否 | 檔案大小（字節） |
| mimeType | String | 否 | MIME 類型 |
| extension | String | 否 | 副檔名 |

**groups[] / groupList[] 字段**：

| 字段名 | 類型 | 必填 | 描述 |
|-|-|-|-|
| groupId | String | 是 | 組合 ID |
| groupName | String | 否 | 組合名稱 |
| coverAssetId | String | 否 | 封面素材 ID |
| assets | Array | 否 | 組合下素材列表；傳入時優先使用 |

**groups[i].assets[] 字段**：

| 字段名 | 類型 | 必填 | 描述 |
|-|-|-|-|
| name | String | 是 | 素材名稱 |
| url | String | 是 | 公網可訪問 `http/https` 地址 |
| size | Number | 否 | 檔案大小（位元組） |
| mimeType | String | 否 | MIME 類型 |
| extension | String | 否 | 副檔名 |

**響應參數**：

| 字段名 | 類型 | 描述 |
|-|-|-|
| taskId | String | 審批任務 ID |

必填字段：

- `templateId`
- `createdBy`
- `assets`（與 `groups/groupList` 二選一，至少一種有效素材來源）
- `assets[].url` 必須為可公開訪問的 `http/https` 地址
- `groups` / `groupList`（組合素材審批）：
  - 每個組合必填 `groupId`
  - 可選 `groupName`、`coverAssetId` 與組合內 `assets`
  - 同時傳頂層 `assets` 與 `groups/groupList` 時，會建立混合主體審批（`mixed_assets`）

請求示例：

```json
{
  "service": "createApproval",
  "templateId": "101",
  "createdBy": "10086",
  "assets": [
    {
      "name": "demo.mp4",
      "url": "https://cdn.example.com/m/asset_1.mp4"
    }
  ]
}
```

成功示例：

```json
{
  "code": "0",
  "message": "成功",
  "result": {
    "taskId": "9527"
  }
}
```

**curl 示例**：

```bash
curl --location --request POST 'https://open.musedam.cc/api/muse/approval-api' \
--header 'Authorization: Bearer your_api_key' \
--header 'Content-Type: application/json' \
--data-raw '{
    "service": "createApproval",
    "templateId": "101",
    "createdBy": "10086",
    "assets": [
      {
        "name": "demo.mp4",
        "url": "https://cdn.example.com/m/asset_1.mp4"
      }
    ]
}'
```

**curl 示例（組合素材審批）**：

    "service": "createApproval",

        "groupId": "group_10001",

          {

## taskStatusQuery

**接口路徑**：`/approval-api`

**請求參數**：

| 字段名 | 類型 | 必填 | 描述 |
|-|-|-|-|
| service | String | 是 | 固定為 `taskStatusQuery` |
| taskId | String | 是 | 審批任務 ID（正整數） |

**響應參數**：

| 字段名 | 類型 | 描述 |
|-|-|-|
| taskId | String | 任務 ID |
| status | String | `PENDING` / `PROCESSING` / `APPROVED` / `REJECTED` / `CANCELED` |
| statusLabel | String | 狀態文案 |
| progressPercent | Number | 進度百分比 |
| currentNodeName | String \| null | 當前節點名稱 |
| currentNodeSignMode | String \| null | 當前節點簽審模式（`and` / `or`） |
| currentNodeProgress | Object | 當前節點統計 |
| currentNodeApprovers | Array | 當前節點審批人狀態列表 |
| operator | String \| null | 最近操作人 |
| updatedAt | String | 更新時間（ISO） |

請求示例：

```json
{
  "service": "taskStatusQuery",
  "taskId": "9527"
}
```

`result.status` 取值：
`PENDING | PROCESSING | APPROVED | REJECTED | CANCELED`。

**curl 示例**：

```bash
curl --location --request POST 'https://open.musedam.cc/api/muse/approval-api' \
--header 'Authorization: Bearer your_api_key' \
--header 'Content-Type: application/json' \
--data-raw '{
    "service": "taskStatusQuery",
    "taskId": "9527"
}'
```

**說明（組合素材查詢）**：組合素材審批任務與一般素材審批任務共用 `taskStatusQuery`，傳入組合任務 `taskId` 即可查詢。

**curl 示例（查詢組合素材審批任務）**：

```bash
curl --location --request POST 'https://open.musedam.cc/api/muse/approval-api' \
--header 'Authorization: Bearer your_api_key' \
--header 'Content-Type: application/json' \
--data-raw '{
    "service": "taskStatusQuery",
    "taskId": "9527"
}'
```

### 訂閱回調 payload 說明

當呼叫 `subscriptionChange` 且 `operation = ADD` 成功後，審批狀態變化會回調到你傳入的 `callbackUrl`。

#### 回調請求基礎約定

- 請求方法：`POST`
- `Content-Type`：`application/json`

回調體結構：

```json
{
  "eventId": "evt_xxx",
  "eventType": "APPROVAL",
  "eventTime": "1760258885000",
  "payload": {
    "eventName": "TASK_APPROVED",
    "orgId": "233",
    "taskId": "9527",
    "taskStatus": "APPROVED"
  }
}
```

字段說明：

| 字段名 | 類型 | 描述 |
|-|-|-|
| eventId | String | 事件唯一 ID（接收方建議按此做冪等） |
| eventType | String | 固定為 `APPROVAL` |
| eventTime | String | 毫秒時間戳字串 |
| payload | Object | 業務資料體 |

#### payload 公共字段

每個回調事件的 `payload` 至少包含：

| 字段名 | 類型 | 描述 |
|-|-|-|
| eventName | String | 事件名 |
| orgId | String | 組織 ID（由系統填充） |
| taskId | String | 審批任務 ID |
| taskStatus | String | 任務狀態：`PROCESSING` / `APPROVED` / `TIMEOUT` |

#### 事件全集（觸發條件）

| eventName | 觸發條件 |
|-|-|
| NODE_STARTED | 節點開始處理時觸發（首節點、正常流轉、重提流轉） |
| APPROVER_SUBMITTED | 審批人在節點提交審批意見時觸發（同一節點可多次觸發） |
| NODE_COMPLETED | 某節點辦結時觸發（通過 / 拒絕） |
| NODE_TRANSFERRED | 節點辦結後流轉到下一處理節點時觸發（正常、重提、超時轉交） |
| SUBMITTER_RESUBMITTED | 發起人在「待重新提交」節點提交新素材時觸發 |
| TASK_APPROVED | 任務終態通過時觸發 |
| NODE_TIMEOUT | 節點超時時觸發（超時轉交或待重新分配） |

#### 字段定義（完整）

##### `payload.node`（節點物件）

| 字段名 | 類型 | 描述 |
|-|-|-|
| nodeId | String | 節點 ID（必有） |
| nodeOrder | Number | 節點順序（部分事件存在） |
| nodeRole | String | 節點角色：`normal` / `resubmit_submitter` / `resubmit_approver`（部分事件存在） |
| nodeStatus | String | 常見值：`pending` / `processing` / `approved` / `rejected` / `timeout_transferred` / `re_assigned` |
| signMode | String | 簽審模式：`and` / `or`（按場景出現） |
| approverCount | Number | 審批人數（按場景出現） |
| approvers | Array | 節點辦結時審批人結果（`NODE_COMPLETED`），子項含 `id` / `name` / `status` |
| startedAt | String | 節點開始時間（ISO） |
| completedAt | String | 節點完成時間（ISO） |
| timeoutHours | Number | 節點超時閾值小時數（超時事件出現） |

##### `payload.approver`（審批人提交物件，`APPROVER_SUBMITTED`）

| 字段名 | 類型 | 描述 |
|-|-|-|
| id | String | 審批人使用者 ID |
| name | String | 審批人名稱 |
| decision | String | 審批決定：`approved` / `rejected` |
| comment | String | 審批意見 |
| submittedAt | String | 提交時間（ISO） |

##### `payload.submitter`（提交人物件，`SUBMITTER_RESUBMITTED`）

| 字段名 | 類型 | 描述 |
|-|-|-|
| id | String | 提交人使用者 ID |
| name | String | 提交人名稱 |
| comment | String | 重提備註 |
| submittedAt | String | 提交時間（ISO） |

##### `payload.timeout`（超時物件）

| 字段名 | 類型 | 描述 |
|-|-|-|
| transferTo | Object \| null | 超時轉交目標；有轉交人時為 `{ "id": "...", "name": "..." }`，無轉交人時為 `null` |

##### `payload.latestAssets`（重提素材快照，`SUBMITTER_RESUBMITTED`）

| 字段名 | 類型 | 描述 |
|-|-|-|
| assetId | String | 素材 ID |
| filePathId | String | 路徑 ID |
| version | Number | 素材版本號 |
| oldStorePath | String | 舊版本儲存路徑 |
| newStorePath | String | 新版本儲存路徑 |
| updatedAt | String | 更新時間（ISO） |

##### `payload.transferReason`（`NODE_TRANSFERRED`）

| 枚舉值 | 描述 |
|-|-|
| NEXT_NODE | 正常流轉到下一審批節點 |
| RESUBMIT_SUBMITTER | 流轉到待重新提交節點 |
| RESUBMIT_APPROVER | 重提後流轉到重審節點 |
| TIMEOUT_TRANSFER | 超時後轉交 |

#### 事件時序（關鍵流程）

說明：回調為「至少一次投遞」，消費方應按 `eventId` 做冪等去重，不要假設不會重複投遞。

##### 正常通過（多節點）

1. `NODE_STARTED`（首節點開始）
2. `APPROVER_SUBMITTED`（每位審批人提交時觸發，可能多次）
3. `NODE_COMPLETED`（當前節點完成）
4. 若有下一節點：`NODE_TRANSFERRED` -> `NODE_STARTED`
5. 重複 2~4，直到最後一個節點完成
6. `TASK_APPROVED`（任務終態通過）

##### 拒絕後重提

1. `APPROVER_SUBMITTED`（`decision = rejected`）
2. `NODE_COMPLETED`（`nodeStatus = rejected`）
3. `NODE_TRANSFERRED`（`transferReason = RESUBMIT_SUBMITTER`）
4. `NODE_STARTED`（`nodeRole = resubmit_submitter`）
5. `SUBMITTER_RESUBMITTED`（提交人重提）
6. `NODE_COMPLETED`（重提節點完成）
7. `NODE_TRANSFERRED`（`transferReason = RESUBMIT_APPROVER`）
8. `NODE_STARTED`（重審節點開始）
9. 後續再次進入正常審批鏈路（`APPROVER_SUBMITTED` ...）

##### 超時轉交 / 超時未轉交

1. 節點超時觸發 `NODE_TIMEOUT`（`taskStatus = TIMEOUT`）
2. 若配置了超時轉交人：緊接著觸發 `NODE_TRANSFERRED`（`transferReason = TIMEOUT_TRANSFER`），任務回到 `PROCESSING`
3. 若無可轉交人：僅有 `NODE_TIMEOUT`（常見 `nodeStatus = re_assigned`），等待人工處理後再推進
