下面的示例可分別使用。將 `your_api_key` 替換為你的 API Key，將示例資源 ID 替換為當前商品庫中的實際 ID。

## 查詢商品列表

密鑰需要先添加為 API Key 協作者，詳見[取得授權](./product-library#authentication-and-scope)。以下請求返回當前角色可見的商品列表。

```bash
curl --request GET 'https://open.musedam.cc/api/product/products?page=1&pageSize=20' \
  --header 'Authorization: Bearer your_api_key'
```

讀取響應中的 `data` 取得商品，讀取 `pagination` 取得分頁信息。`view_only` 和 `usable` 角色只能查看已發佈商品。

## 創建品牌、分類和模板

創建品牌需要 `manage` 角色。

```bash
curl --request POST 'https://open.musedam.cc/api/product/brands' \
  --header 'Authorization: Bearer your_api_key' \
  --header 'Content-Type: application/json' \
  --data-raw '{"name":"Example brand"}'
```

響應中的 `data.id` 是品牌 ID。分類和模板的創建參數見[商品分類](./product-library-categories)與[商品信息模板](./product-library-template-writes)，無需為了調用商品接口重新創建已有資源。

## 查找素材

創建或編輯商品前，可以查找已有圖片素材。此接口需要 `editable` 或 `manage` 角色。

```bash
curl --request GET 'https://open.musedam.cc/api/product/assets?mimeType=image%2F&pageSize=20' \
  --header 'Authorization: Bearer your_api_key'
```

將響應中的素材 `id` 用作商品的 `coverAssetId` 或 `imageAssetIds`。返回的 `previewUrl` 用於預覽。

## 創建商品

創建商品需要 `editable` 或 `manage` 角色。以下示例使用品牌 `10`、該品牌下的分類 `20` 和圖片素材 `30`，請替換為已有資源 ID。

```bash
curl --request POST 'https://open.musedam.cc/api/product/products' \
  --header 'Authorization: Bearer your_api_key' \
  --header 'Content-Type: application/json' \
  --header 'Idempotency-Key: create-product-001' \
  --data-raw '{"name":"Example product","spu":"EXAMPLE-001","brandId":10,"categoryId":20,"coverAssetId":30,"imageAssetIds":[30]}'
```

新商品為草稿，商品 ID 位於 `data.id`。同一次創建失敗後重試時，保持請求體和 `Idempotency-Key` 不變；創建另一個商品時使用新的冪等鍵。

## 更新與發佈商品

更新商品 `40` 的說明：

```bash
curl --request PATCH 'https://open.musedam.cc/api/product/products/40' \
  --header 'Authorization: Bearer your_api_key' \
  --header 'Content-Type: application/json' \
  --data-raw '{"description":"New product description"}'
```

省略的字段保持原值。允許為空的字段可傳 `null` 清空，媒體列表可傳 `[]` 清空。需要防止覆蓋併發修改時，可通過 `If-Match` 傳入讀取時返回的 `ETag`，詳見[寫入與錯誤處理](./product-library-write-conventions)。

發佈商品 `40`：

```bash
curl --request PATCH 'https://open.musedam.cc/api/product/products/40/status' \
  --header 'Authorization: Bearer your_api_key' \
  --header 'Content-Type: application/json' \
  --data-raw '{"status":"published"}'
```

發佈前需填寫模板要求的必填字段，並確保素材有效。校驗失敗時返回 `422` 和字段詳情，商品保持原狀態。

## 讀取商品與預覽

取得商品 `40` 的詳情：

```bash
curl --request GET 'https://open.musedam.cc/api/product/products/40' \
  --header 'Authorization: Bearer your_api_key'
```

使用商品媒體中的 `previewUrl` 展示預覽。具備下載權限時，媒體還可能包含 `downloadUrl` 和 `downloadUrlExpiresAt`。鏈接過期後重新讀取商品即可。

## 分享、導出和下載

為已發佈商品 `40` 創建一個有效期為 7 天、不可下載的分享，需要 `usable` 及以上角色：

```bash
curl --request POST 'https://open.musedam.cc/api/product/product-shares' \
  --header 'Authorization: Bearer your_api_key' \
  --header 'Content-Type: application/json' \
  --data-raw '{"productIds":[40],"expiresInDays":7,"allowDownload":false}'
```

響應中的 `data.url` 是分享鏈接。

將商品 `40` 導出為 Excel，需要 `usable` 及以上角色：

```bash
curl --request POST 'https://open.musedam.cc/api/product/product-downloads' \
  --header 'Authorization: Bearer your_api_key' \
  --header 'Content-Type: application/json' \
  --data-raw '{"kind":"export","productIds":[40],"format":"xlsx","includeAssetUrls":false}' \
  --output 'products.xlsx'
```

示例將結果保存為 `products.xlsx`，不包含素材鏈接。`format` 也支持 `csv` 和 `json`。

下載商品 `40` 的原文件，需要 `usable` 及以上角色：

```bash
curl --request POST 'https://open.musedam.cc/api/product/product-downloads' \
  --header 'Authorization: Bearer your_api_key' \
  --header 'Content-Type: application/json' \
  --data-raw '{"kind":"assets","productIds":[40]}' \
  --output 'product-download'
```

結果保存為 `product-download`。只有一個文件時返回原文件，多個文件時返回 ZIP，可按實際文件類型修改保存名稱。

## 了解商品的模板版本

商品創建時會保存所用模板的版本。後續修改或刪除模板，不會改變已有商品的字段定義。通過商品詳情中的 `templateDefinition` 讀取該版本，詳見[商品信息模板](./product-library-template-writes)。

## 同步商品

首次同步從以下請求開始：

```bash
curl --request GET 'https://open.musedam.cc/api/product/products?sync=true&pageSize=100' \
  --header 'Authorization: Bearer your_api_key'
```

如果 `pagination.nextCursor` 不為 `null`，將其完整值替換下面的 `your_cursor`，繼續讀取下一頁：

```bash
curl --get 'https://open.musedam.cc/api/product/products' \
  --header 'Authorization: Bearer your_api_key' \
  --data-urlencode 'sync=true' \
  --data-urlencode 'cursor=your_cursor'
```

繼續使用每次返回的 `nextCursor`，直到其為 `null`，即使某一頁的 `data` 為空也應繼續。所有頁面處理完成後，原樣保存 `pagination.syncedUntil`；下次同步在首請求中將它作為 `updatedAfter` 傳入。時間戳需保留完整精度，完整規則見[商品同步](./product-library-synchronization)。

## 核對商品可見性

同步不會返回已刪除商品的記錄。定期檢查本地保存的商品 ID：

```bash
curl --request POST 'https://open.musedam.cc/api/product/products/visibility' \
  --header 'Authorization: Bearer your_api_key' \
  --header 'Content-Type: application/json' \
  --data-raw '{"ids":[40,41]}'
```

響應為 `not_visible` 的商品應從本地副本移除。該狀態也可能表示草稿不可見或無訪問權限，不應據此推斷商品是否存在。如需刪除商品本身，參見[商品操作指南](./product-library-product-writes)。

## 處理常見錯誤

| 狀態碼 | 處理方式 |
| --- | --- |
| 401 / 403 | 檢查 API Key 狀態與協作者角色。 |
| 412 | 重新讀取商品，核對變更後使用新的 ETag 重試。 |
| 422 | 檢查請求參數；若回應含 `details`，依 `details[].field` 和 `details[].message` 修正。 |
| 409 | 根據 `code` 處理衝突；若為 `mutation_response_unavailable`，先讀取並核對結果。 |

保留響應中的 `requestId` 便於排查。完整說明見[錯誤碼](./product-library-write-conventions#error-catalog)。
