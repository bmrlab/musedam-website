## 常見錯誤及處理方法

### API 認證錯誤

| 錯誤碼 | 錯誤描述 | 處理方法 |
|-|-|-|
| MB100002 | 沒有權限訪問該資源 | 檢查 API Key 是否正確，是否具有訪問該資源的權限 |
| 401 | Unauthorized | API Key 無效或已過期，需要更新 API Key |

### 請求參數錯誤

| 錯誤碼 | 錯誤描述 | 處理方法 |
|-|-|-|
| MB100001 | 請求參數不正確 | 檢查請求參數格式、類型是否符合API要求 |
| MB100003 | 資源不存在 | 檢查請求的資源ID是否存在或已被刪除 |

### 業務邏輯錯誤

| 錯誤碼 | 錯誤描述 | 處理方法 |
|-|-|-|
| MB100004 | 資源不支持該操作 | 檢查操作是否適用於當前資源類型 |
| MB100005 | 業務處理失敗 | 根據錯誤信息調整業務邏輯或重試 |

### 系統級錯誤

| 錯誤碼 | 錯誤描述 | 處理方法 |
|-|-|-|
| MS100001 | 系統異常 | 稍後重試，如持續出現請聯繫技術支持 |
| MS100003 | 系統繁忙 | 實施請求限流，延遲重試 |

## 排查順序

1. 檢查 HTTP 狀態、業務 `code` 與 `message`，保存 `traceId`。
2. 驗證域名、請求方法、請求體類型和密鑰授權範圍。
3. 檢查資源是否屬於當前企業，及相應產品能力是否已開通。
4. 對臨時系統故障使用有上限的重試；參數或權限錯誤修復後再請求。

原始示例中的成功業務碼存在 `0`、`"0"` 與 `"200"` 等寫法。請按具體接口確認成功判斷邏輯，不要僅憑 HTTP 200 判定業務成功。
