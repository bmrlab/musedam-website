## 快速接入

商品庫全部 28 個操作統一使用 POST `https://open.musedam.cc/api/muse/product-api`。透過 `service` 指定下文的操作識別碼，所有業務參數放在扁平 JSON 請求本文中。

1. 取得 MuseDAM API Key。
2. 請商品庫管理員在「成員設定 → 新增成員」中，將該密鑰新增為 API Key 協作者，並指派所需角色。
3. 從伺服器端呼叫接口，在請求標頭中攜帶 `Authorization: Bearer <APIKEY>`。

權限按密鑰在 “成員設置” - “角色與權限” 中的設置

依需要選擇角色：

| 角色 | 可執行的操作 |
| --- | --- |
| `view_only` | 檢視品牌、分類、資訊範本及已發佈商品；核對商品 ID 可見性。 |
| `usable` | 包含 `view_only` 全部操作，另可在讀取商品時取得原檔簽名下載連結（`downloadUrl`），以及建立商品分享（`createProductShare`）。 |
| `editable` | 包含 `usable` 全部操作，另可查詢素材庫素材（`listAssets` / `getAsset`）、建立和編輯商品、存取草稿、發佈或退回草稿及軟刪除商品。 |
| `manage` | 管理全部資源，包括新增/修改/刪除品牌、分類、資訊範本，撤銷分享，以及查詢團隊分享與下載記錄。 |

每個角色包含上一級角色的權限。後續範例中的資源 ID 需替換為實際值。

將 `your_api_key` 替換為已授權的 API Key，查詢商品列表：

```bash
curl --request POST 'https://open.musedam.cc/api/muse/product-api' \
  --header 'Authorization: Bearer your_api_key' \
  --header 'Content-Type: application/json' \
  --data-raw '{
  "service": "listProducts",
  "page": 1,
  "pageSize": 20
}'
```

成功回應使用 HTTP 200，JSON 中 `code` 為 `"0"`，`message` 範例為 `"OK"`，`result.success` 為 `true`，商品資料位於 `result.data`，分頁資訊位於 `result.pagination`。列表為空時，請先確認商品庫中是否有目前角色可見的商品；`view_only` 和 `usable` 只能檢視已發佈商品。

## 請求與回應

所有介面統一使用 `POST https://open.musedam.cc/api/muse/product-api`，請求標頭攜帶 `Authorization: Bearer <APIKEY>` 和 `Content-Type: application/json`。`service` 與所有業務參數平鋪在 JSON 請求本文頂層。

**成功回應範例**：

```json
{
  "code": "0",
  "message": "OK",
  "result": {
    "success": true,
    "data": {},
    "code": null,
    "message": null,
    "requestId": "request_123"
  },
  "traceId": "trace_123"
}
```

**權限不足的閘道失敗回應範例（HTTP 200，診斷文案僅為示意）**：

```json
{
  "code": "MB100005",
  "message": "product-library HTTP 403: {\"code\":\"0\",\"result\":{\"success\":false,\"data\":null,\"code\":\"forbidden\",\"message\":\"Insufficient permissions\",\"requestId\":\"request_123\"}}",
  "result": null,
  "traceId": "trace_123"
}
```

| 欄位 | 類型 | 說明 |
| --- | --- | --- |
| `code` | String | 公開閘道碼：成功為 `"0"`，上游失敗為 `"MB100005"`，無效憑證為 `"MO100002"`。 |
| `message` | String | 成功範例為 `"OK"`；文案僅供診斷，不應解析或用於分支判斷。 |
| `result` | Object / null | 成功時包含業務結果；閘道錯誤時為 `null`。 |
| `result.success` | Boolean | 成功 `true`，失敗 `false`。 |
| `result.data` | Object / Array | 成功時依介面回傳物件或陣列。 |
| `result.code` | null | 成功時為 `null`；內部錯誤碼見[疑難排解參考](#error-catalog)，不是公開錯誤結果欄位。 |
| `result.message` | null | 成功時為 `null`；閘道錯誤時沒有此欄位。 |
| `result.pagination` | Object | 列表與同步介面成功時回傳的分頁資訊。 |
| `result.requestId` | String | 請求 ID。 |
| `traceId` | String | 鏈路追蹤 ID。 |

一般列表介面支援 `page`（預設 `1`）和 `pageSize`（預設 `20`，最大 `100`），在 `result.pagination` 中回傳分頁統計。需要持續增量同步商品時，請使用[游標同步](#cycle-protocol)。

```json
{
  "page": 1,
  "pageSize": 20,
  "totalCount": 42,
  "totalPages": 3
}
```

<details id="error-catalog">
<summary>請求限制與內部錯誤碼（疑難排解參考）</summary>

下表及後續操作說明中的 401、403、404、409、413、422、500、503 均指商品庫內部狀態與 `result.code`，僅供疑難排解，不是公開 HTTP 狀態或閘道錯誤結構。公開錯誤契約見上文，不要解析 `message` 中嵌入的內部回應。

請求本文上限為 1 MiB。寫入介面、歷史記錄介面和游標同步介面拒絕未知欄位；一般列表和詳情讀取介面忽略未知欄位。

| HTTP 狀態碼 | `result.code` | 說明與處理方式 |
| --- | --- | --- |
| 401 | `invalid_credentials` | API Key 無效或缺失，檢查 `Authorization: Bearer` 請求標頭。 |
| 401 | `key_inactive` | API Key 已停用或已過期。 |
| 403 | `forbidden` | 目前協作者角色權限不足，或資源不可見。 |
| 404 | `not_found` | 資源不存在、已刪除或目前角色不可存取。 |
| 409 | `sku_in_use` | 商品 `spu` 已被占用（含軟刪除商品）。 |
| 409 | `code_in_use` | 資源編碼衝突，請重試或更換編碼。 |
| 409 | `name_in_use` | 同層分類名稱或範本名稱已存在。 |
| 409 | `brand_has_dependents` | 品牌下仍有有效分類或商品，需先移除或遷移。 |
| 409 | `category_has_products` | 分類子樹下仍有有效商品，需先移除或遷移。 |
| 409 | `default_template_replacement_required` | 刪除商品庫預設範本但未提供 `replacementForLibraryDefault` 時回傳（若傳入的替代範本不存在、已刪除或為被刪除範本自身，則回傳 `422 validation_failed`）。 |
| 409 | `mutation_response_unavailable` | 變更已提交（`result.mutationOutcome: "committed"`），但無法回傳結果；請先查詢核對狀態，切勿重複提交。 |
| 413 | `payload_too_large` | 請求本文超過 1 MiB 上限。 |
| 422 | `validation_failed` | 參數驗證失敗，根據 `result.message` 中的欄位詳情修正輸入。 |
| 503 | `authentication_unavailable` | 驗證服務暫時不可用，請稍後重試。 |
| 503 | `write_conflict` | 寫入鎖衝突已回滾，等待後重試；公開閘道不保證轉送 `Retry-After`。 |
| 500 | `internal_server_error` | 伺服器端異常，請保留 `traceId` 與 `result.requestId` 排查，重試寫入前先核對狀態。 |

</details>

## 分類

<details id="category-rules">
<summary>分類樹與刪除</summary>

同級名稱必須唯一，父分類必須屬於同一品牌。分類最多 10 級，每個品牌最多 5000 個未刪除節點。`sortOrder` 是從零開始的同級位置；建立或移動時省略則附加，同父層更新時省略則保持位置。改名或移動會更新後代路徑。

建立時，只有商品庫預設模板未綁定品牌或已綁定目前品牌，才新增直接模板綁定；否則仍建立成功，按祖先分類、品牌、商品庫預設模板查找。刪除會軟刪除整棵子樹；其中有未刪除商品時回傳 `409 category_has_products`，不執行刪除。

</details>

## 信息模板

<details id="template-groups">
<summary>分組 groups</summary>

`groups` 包含 1–200 個分組，一個模板的欄位總數最多為 200。

| 欄位 | 類型 | 說明 |
| --- | --- | --- |
| `id` | string | 現有分組必填，1–128 個字元，必須屬於本模板；新分組不傳。 |
| `name` | string | 必填，1–128 個字元，去除首尾空白。 |
| `fields` | array | 必填，分組中的欄位，見下表。 |

現有分組保持原有順序，新分組按提交順序附加。分組不接受 `sortOrder` 或 `isDefault`。預設分組由伺服器指定，不能刪除。

</details>

<details id="template-fields">
<summary>欄位 fields</summary>

新欄位必須提供 `key`、`name` 和 `type`。更新現有欄位時必須傳 `id`。類型不變時，省略的屬性保留原值，`sortOrder` 除外；變更 `type` 時，`config` 會按目標類型遷移，必要時須明確提供新設定。

| 欄位 | 類型 | 說明 |
| --- | --- | --- |
| `id` | string | 現有欄位必填，1–128 個字元，必須屬於目前分組；新欄位不傳。 |
| `key` | string | 新欄位必填，1–64 個字元（校驗前去除首尾空白），僅允許英文字母、數字和底線（`^[a-zA-Z0-9_]+$`），在模板內唯一；既有欄位不能修改。 |
| `name` | string | 新欄位必填，1–128 個字元。 |
| `type` | string | 新欄位必填，支援的類型見下方設定表。 |
| `required` | boolean | 選填；新欄位預設為 `false`。 |
| `placeholder` | string | 選填，最多 255 個字元；更新時省略以保留原值，新欄位回應預設為 `null`。 |
| `sortOrder` | integer | 選填，同組內唯一的非負整數；省略時使用欄位在陣列中的位置。 |
| `config` | object | 按欄位類型填寫，見下方設定表；新欄位省略時使用 `{}`，但仍須滿足該類型的設定要求。 |
| `typeChangeConfirmed` | boolean | 選填；允許但需要確認的類型變更須傳 `true`。 |

建立時會自動加入名稱（`name`）、SKU（`sku`）和主圖（`mainImage`）三個受保護的系統欄位，因此最多可新增 197 個自訂欄位。第一個分組的自訂欄位排列在這三個欄位之後，傳入的 `sortOrder`（省略時為陣列位置）會增加 3。替換定義（`updateTemplate`）時須保留模板中所有現有系統欄位的 `id`、`type`、`required` 和 `config`（系統欄位的上述屬性均不可透過 Open API 修改）。欄位不能移到其他分組。

新欄位只能是自訂欄位，不能使用保留的系統 `key`（`name`、`sku`、`brand`、`category`、`description`、`mainImage`）。`isSystemField` 和 `systemKey` 不能用於建立或重新分配系統身分；更新現有系統欄位時若傳入須與原值一致，自訂欄位請省略。未知的分組或欄位屬性會被拒絕。

</details>

<details id="field-configuration">
<summary>欄位設定 config</summary>

設定由欄位的 `type` 決定。例如，文字欄位使用 `{}`，貨幣和選項欄位需要額外設定。

| 欄位類型 | config 設定 |
| --- | --- |
| `text`、`textarea`、`email`、`phone`、`url`、`color`、`date`、`dateRange` | 使用 `{}`，不接受其他設定。 |
| `number` | 選填 `unit`，字串。 |
| `currency` | 必填 `code`、`symbol`（非空字串）和 `decimals`（0–4 的整數）。 |
| `richtext` | 必填 `mode`，取值為 `html` 或 `delta`。 |
| `select`、`radio`、`checkbox` | 必填非空 `options` 陣列。每項見下表，`value` 不得重複。 |
| `image`、`file` | 選填 `maxCount`（大於等於 1 的整數）、`maxSizeMB`（大於 0 的數字）和 `accept`（字串陣列）。 |

每個 `options` 元素包含：

| 欄位 | 類型 | 說明 |
| --- | --- | --- |
| `value` | string | 必填，非空，選項的唯一值。 |
| `label` | string | 必填，非空，顯示名稱。 |
| `sortOrder` | integer | 必填，非負整數。 |
| `archived` | boolean | 選填，是否封存該選項。 |

所有系統欄位在更新模板（`updateTemplate`）時必須保持原有的 `type`、`required` 與 `config` 不變，不支援透過 Open API 修改系統欄位的 `config`。

空設定和系統設定拒絕未知屬性；其他設定及選項會移除未知屬性。完整機器可讀定義可下載 [OpenAPI JSON](/assets/developers/product-library/openapi.json)。

</details>

<details id="template-definition">
<summary>回傳的模板定義</summary>

模板詳情的 `groups` 和商品的 `templateDefinition.groups` 均包含分組與欄位。商品回傳的是建立時固定的版本，後續模板修改或刪除不會改變它；未綁定模板時，`templateDefinition` 可為 `null`。

分組固定回傳 `id`、`name`、`fields`，以及以下唯讀屬性：

| 欄位 | 類型 | 說明 |
| --- | --- | --- |
| `isDefault` | boolean | 是否為預設分組。 |
| `sortOrder` | integer | 分組順序。 |

每個欄位固定回傳 `id`、`key`、`name`、`type`、`required`、`placeholder`、`sortOrder`、`config`，以及以下屬性；不回傳寫入參數 `typeChangeConfirmed`。

| 欄位 | 類型 | 說明 |
| --- | --- | --- |
| `isSystemField` | boolean | 是否為系統欄位。 |
| `systemKey` | string 或 null | 系統身分：`name`、`sku`、`brand`、`category`、`description`、`mainImage`；自訂欄位為 `null`。 |

`placeholder` 可為 `null`。設定中的媒體引用會回傳安全的預覽資訊，不包含儲存路徑或憑證。

</details>

<details id="fields-Template">
<summary>Template 回傳欄位</summary>

| 欄位名 | 類型 | 描述 |
| - | - | - |
| id | String | 資源 ID。最短 1 個字元；最長 128 個字元 |
| name | String | 名稱。 |
| description | String | 說明。可為 null |
| enabled | Boolean | 是否啓用模板。 |
| isSystemDefault | Boolean | 是否為系統預設範本。 |
| isLibraryDefault | Boolean | 是否為商品庫預設範本。 |
| createdAt | String | RFC 3339 時間字串；保留完整精度。|
| updatedAt | String | RFC 3339 時間字串；保留完整精度。|
| boundBrandIds | List&lt;Integer&gt; | 綁定的品牌 ID。每個元素：正整數 ID，最大 2147483647。 |
| boundCategoryIds | List&lt;Integer&gt; | 綁定的分類 ID。每個元素：正整數 ID，最大 2147483647。 |
| groups | List&lt;VersionGroup&gt; | 模板分組。巢狀欄位：[範本分組與欄位](#template-definition) |

</details>

## 商品

<details id="template-pins-and-field-values">
<summary>模板版本與自訂欄位</summary>

商品建立時儲存模板版本。讀取 `templateDefinition` 解釋 `templateFields`；後續模板變更或刪除不影響這個版本，`updateProduct` 不能更換模板。`templateFields` 以固定版本中的**自訂欄位 ID**（`isSystemField: false` 的 `field.id`）為鍵，更新時淺合併；省略的欄位保持不變。系統欄位（`name`、`sku`、`brand`、`category`、`description`、`mainImage`）必須透過頂層請求參數傳入，傳入 `templateFields` 會被拒絕。

明確提供的 `templateId` 優先；否則，有 `categoryId` 時依次查找分類、祖先分類、品牌和商品庫預設模板。沒有分類時只考慮商品庫預設模板，即使傳入了品牌。

| 欄位類型 | 輸入格式與校驗規則 |
| --- | --- |
| `text`、`textarea`、`phone` | 字串，儲存時去除首尾空白；空字串或純空白清空為 `null`，不要求電話號碼正規表示式。 |
| `email` | 合法電子郵件格式字串，不接受空字串清空。 |
| `url` | `http://` 或 `https://` 開頭的合法 URL 字串，不接受空字串清空。 |
| `color` | 十六進位顏色字串，支援 `#RGB`、`#RRGGBB`、`#RRGGBBAA`，不接受空字串清空。 |
| `number`、`currency` | 僅接受有限 JSON 數字，不接受數字字串或空字串。 |
| `date` | 有效日曆日期 `YYYY-MM-DD` 或以該日期及 `T` 開頭的有效日期時間字串，不接受空字串清空。 |
| `dateRange` | 恰好兩個上述有效日期字串組成的陣列 `[start, end]`，須滿足 `start <= end`；不接受物件或 `[]` 清空。 |
| `select`、`radio` | 單一字串，必須匹配欄位 `config.options` 中的選項 `value`；不保證空字串清空。 |
| `checkbox` | 選項 `value` 字串陣列，每項須存在於欄位 `config.options` 中；`[]` 清空。 |
| `image`、`file` | 素材查詢介面回傳的素材 `id` 陣列；`[]` 清空。 |
| `richtext` | `html` 模式為原樣儲存的字串（不裁剪空白）；`delta` 模式為 `{ "ops": [...] }`，`ops` 是物件陣列，內部可包含 `null`。 |

所有自訂欄位的輸入值均不接受根值 `null`；省略欄位可保留原值。

草稿可缺少必填值，但提交和合併後的欄位仍須滿足類型／選項規則；發布或編輯已發布商品會驗證完整商品。一次寫入的全部媒體引用（`coverAssetId`、`imageAssetIds`、`relatedAssetIds` 及所有自訂 `image`/`file` 欄位）合計最多 100 個，只接受本商品庫既有的素材 ID（`listAssets` 回傳的 `id`）。媒體列表省略時保留，`[]` 清空；未傳 `coverAssetId` 時，首張 `imageAssetIds` 圖片成為封面。

</details>

<details id="cycle-protocol">
<summary>同步與檢查點</summary>

1. 首次使用 `"sync": "true"`，省略 `updatedAfter`；增量週期傳入上次完成的 `result.pagination.syncedUntil`。
2. 按商品 `id` 和 `updatedAt` 合併，保留較新版本。
3. 使用 `"sync": "true", "cursor": "<nextCursor>"` 跟隨 `result.pagination.nextCursor` 直到 null；即使 `result.data` 為空，也要繼續。
4. 完成後原樣儲存 `result.pagination.syncedUntil`，不要改用最後一筆商品的時間。

游標綁定密鑰、角色、商品庫、篩選條件和頁面大小；續頁時不要變更它們。更換授權或篩選條件要開始新週期；範圍擴大時重新完整同步。檢查點和同步 `updatedAt` 保留完整六位小數，不要用 JavaScript Date 截斷精度。每週期讀取目前狀態的 `[updatedAfter, syncedUntil)`，上界為首次請求時伺服器時間減 30 秒；長交易仍可能影響完整性，不提供每次變更的事件串流。


同步請求在 `result.data` 中回傳商品列表，在 `result.pagination` 中回傳同步中繼資料：`pageSize`、`syncedUntil`、`nextCursor` 和 `hasMore`。續頁時將回傳的 `result.pagination.nextCursor` 原樣填入下一次請求的 `cursor` 欄位，不要重新命名請求欄位或使用 `result` 包裝業務參數。

</details>

<details id="reconciling-removals">
<summary>清理已刪除或不可見的商品</summary>

同步不會回傳刪除事件。定期將本機商品 ID 交給[核對已知商品 ID](#operation-checkProductVisibility)，`not_visible` 時移除本機副本。該介面不檢查品牌、分類或搜尋等業務篩選；若只維護篩選後的副本，須定期完整核對篩選結果，或同步全部可見商品後在本機篩選。

</details>

<details id="media-and-expiry">
<summary>預覽與下載鏈接</summary>

展示商品媒體時使用 `previewUrl`。需要原文件時，檢查 `downloadUrl`；能預覽不等於有下載權限。

| 鏈接 | 返回條件 | 服務簽發鏈接的有效期上限 |
| --- | --- | --- |
| 派生預覽 | 具備相應查看權限 | 3600 秒 |
| 圖片原圖預覽回退 | 僅適用於圖片，`view_only` 也可能返回 | 300 秒 |
| `downloadUrl` | 關聯可解析且可見，角色為 `usable`、`editable` 或 `manage` | 300 秒 |

所有服務簽發鏈接還受 API key 的到期時間限制。鏈接過期後重新獲取商品數據，不要將簽名 URL 當作素材 ID 保存。

<details>
<summary>鏈接缺失、舊版媒體和外部預覽如何處理？</summary>

- 非圖片素材只返回派生預覽，原始 PDF、壓縮包和文檔不會作為預覽回退。素材庫素材查詢和模板配置只包含預覽。
- 缺少下載權限（如 `view_only` 角色）或關聯無法解析時，會省略 `downloadUrl` 和 `downloadUrlExpiresAt`；具備權限（`usable`、`editable` 或 `manage` 角色）但原文件不可用時，這些值可能為 null。
- 已存儲的外部 DAM 縮略圖或預覽，只對未設置過期時間的 API key 返回，並先排除已知原文件 URL。它們的有效期由第三方控制，不保證短有效期，也不保證校驗提供方簽名。
- API key 設置了 `expiresAt` 時，過期時間無法驗證的外部預覽返回 null。查詢參數中形似簽名的值不能作為可信的過期依據。
- 服務簽發的鏈接仍遵守上表限制；簽名失敗時不會返回原始存儲 URL。

</details>

### 獲取或同步商品列表

**介面路徑**： https://open.musedam.cc/api/muse/product-api

**請求方式**： POST

**介面描述**：普通分頁按 updatedAt/id 降序排序。sync: "true" 時按 (updatedAt,id) 升序排序，使用包含的下界和不包含的固定上界（伺服器時鐘減 30 秒）。全量掃描時省略 updatedAfter；請持續跟隨每個 nextCursor，即使 data 頁為空。游標綁定 key/角色/商品庫/篩選條件/pageSize/邊界。僅在遍歷完畢後原樣保存 syncedUntil；按 id 和 updatedAt 進行重放/去重。持續時間超過 30 秒安全視窗的長交易可能跨越同步週期邊界。見[同步說明](#cycle-protocol)。view_only/usable 僅可見已發佈商品。

所需角色：所有協作者角色。

**請求參數**：

以下業務欄位與 `service` 同層，直接放入 JSON 請求本文，不要使用 `params` 或 `data` 包裝。

| 參數名 | 類型 | 必填 | 描述 |
| - | - | - | - |
| service | String | 是 | 服務識別碼，固定為 `listProducts`。 |

| 欄位名 | 類型 | 描述 |
| - | - | - |

| nextCursor | String | 下一頁游標，掃描結束後為 null。最長 8,192 個字元；可為 null |
| hasMore | Boolean | 是否還有下一頁同步數據。 |

### 部分更新商品

**介面路徑**： https://open.musedam.cc/api/muse/product-api

**請求方式**： POST

**介面描述**：合併頂層純量/自訂欄位，並替換所提交的媒體列表。始終依據商品建立時固定的模板版本定義進行校驗（即使原模板後續已被刪除）。更新已發佈商品時商品將保持已發佈狀態，且合併後的完整商品狀態必須一次性通過所有必填欄位與媒體校驗。本介面不支援切換商品狀態（`status`）或更換模板（`templateId` / `templateVersionId`）。

所需角色：editable 或 manage。

**請求參數**：

以下業務欄位與 `service` 同層，直接放入 JSON 請求本文，不要使用 `params` 或 `data` 包裝。省略的欄位保持不變；**除 `service` 和 `id` 外，至少需傳入一個待更新欄位**。支援清空的欄位可傳空字串 `""` 或空陣列 `[]`。`templateFields` 採用按自訂欄位 ID 淺合併；媒體陣列替換對應槽位。若提供 `imageAssetIds` 但未提供 `coverAssetId`，則第一張圖片成為封面。更新已發佈商品時會保持已發佈狀態並校驗最終完整狀態。不接受 `templateId`、`templateVersionId` 和 `status`。

不接受未定義欄位。

| 參數名 | 類型 | 必填 | 描述 |
| - | - | - | - |
| service | String | 是 | 服務識別碼，固定為 `updateProduct`。 |
| id | Integer | 是 | 正的有符號 32 位資源 ID。正整數 ID，最大 2147483647。 |
| name | String | 否 | 會去除首尾空白；草稿可省略或為空。最長 255 個字元 |
| spu | String | 否 | 會去除首尾空白；空白表示清除。在目前商品庫所有商品（含已刪除商品）中唯一。最長 64 個字元 |
| description | String | 否 | 商品描述。傳空字串 `""` 可清空為 `null`。 |
| brandId | Integer | 否 | 正整數 ID，最大 2147483647。 |
| categoryId | Integer | 否 | 正整數 ID，最大 2147483647。 |
| ownerUserId | Integer | 否 | 正整數 ID，最大 2147483647。 |

| coverAssetId | Integer | 否 | 正整數 ID，最大 2147483647。 |
| imageAssetIds | List&lt;Integer&gt; | 否 | 每個元素：正整數 ID，最大 2147483647；最多 100 項 |
| relatedAssetIds | List&lt;Integer&gt; | 否 | 每個元素：正整數 ID，最大 2147483647；最多 100 項 |

| 參數名 | 類型 | 必填 | 描述 |
| - | - | - | - |
| service | String | 是 | 服務識別碼，固定為 `listProductDownloads`。 |
| productId | Integer | 否 | 按一個商品 ID 篩選記錄，仍返回包含其他商品和文件的完整操作。省略時查詢當前團隊全部記錄。正整數 ID，最大 2147483647。 |
| page | Integer | 否 | 頁碼，正整數，預設 1 |
| pageSize | Integer | 否 | 每頁筆數，正整數，預設 20，上限 100。 |

**回應參數**： `200`，`result.data`：List&lt;ProductDownloadRecord&gt;。 [欄位說明](#fields-ProductDownloadRecord) 分頁欄位見[請求與回應](#wire-format-and-identifiers)。

請求範例：

```bash
curl --request POST 'https://open.musedam.cc/api/muse/product-api' \
  --header 'Authorization: Bearer your_api_key' \
  --header 'Content-Type: application/json' \
  --data-raw '{
  "service": "listProductDownloads",
  "page": 1,
  "pageSize": 20
}'
```
