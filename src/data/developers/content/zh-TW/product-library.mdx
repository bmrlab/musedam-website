## 快速接入

商品庫全部 31 個操作統一使用 POST `https://open.musedam.cc/api/muse/product-api`。透過 `service` 指定下文的操作識別碼，所有業務參數放在扁平 JSON 請求本文中。

1. 取得 MuseDAM API Key。
2. 請商品庫管理員在「成員設定 → 新增成員」中，將該密鑰新增為 API Key 協作者，並指派所需角色。
3. 從伺服器端呼叫接口，在請求標頭中攜帶 `Authorization: Bearer <APIKEY>`。

權限依密鑰所屬團隊和協作者目前角色驗證，請求參數不能切換商品庫。

新加入的協作者預設為 `view_only`。依需要選擇角色：

| 角色 | 可執行的操作 |
| --- | --- |
| `view_only` | 檢視已發佈商品。 |
| `usable` | 檢視、分享和下載已發佈商品。 |
| `editable` | 建立和編輯商品、存取草稿、發佈及刪除商品。 |
| `manage` | 管理全部資源，包括品牌、分類、資訊範本及活動記錄。 |

每個角色包含上一級角色的權限。後續範例中的資源 ID 需替換為實際值。

將 `your_api_key` 替換為已授權的 API Key，查詢商品列表：

```bash
curl --request POST 'https://open.musedam.cc/api/muse/product-api' \
  --header 'Authorization: Bearer your_api_key' \
  --header 'Content-Type: application/json' \
  --data-raw '{
  "service": "listProducts",
  "page": 1,
  "pageSize": 20
}'
```

請求成功時，`success` 為 `true`，`data` 為商品列表，`pagination` 為分頁資訊。列表為空時，請先確認商品庫中是否有目前角色可見的商品；`view_only` 和 `usable` 只能檢視已發佈商品。

## 請求與回應

所有請求均使用您自己的 MuseDAM API Key，攜帶 `Authorization: Bearer <APIKEY>` 和 `Content-Type: application/json`。全部操作使用相同的公開 POST 位址；資源 ID、分頁、篩選和寫入欄位均為 JSON 請求本文欄位，與必填的 `service` 同層。

JSON 接口使用以下結構。下載和匯出成功時直接回傳檔案。

| 回傳內容 | 讀取方式 |
| --- | --- |
| 操作成功 | `success: true`，從 `data` 讀取結果；`code`、`message` 為 `null`。 |
| 操作失敗 | `success: false`，`data: null`；依 HTTP 狀態碼和 `code` 處理，不依賴 `message` 的文案。 |
| 參數驗證失敗 | 若回應包含 `details`，可依 `details[].field` 和 `details[].message` 修正欄位。 |
| 請求追蹤 | 保留 `requestId` 或回應標頭 `X-Request-Id`，用於排查問題。 |

一般列表使用 `page` 和 `pageSize`，在回應頂層回傳 `pagination`。其中 `totalCount` 為總筆數，`totalPages` 為總頁數：

| 參數 | 預設值 | 範圍 |
| --- | --- | --- |
| `page` | `1` | 從 `1` 開始的整數。 |
| `pageSize` | `20` | 正整數，超過 `100` 時以 `100` 處理。 |

```json
{
  "page": 1,
  "pageSize": 20,
  "totalCount": 42,
  "totalPages": 3
}
```

商品和素材可能在請求期間變為不可見，因此實際回傳筆數可能少於 `pageSize`，計數仍保留分頁時的結果。單一資源不可見時回傳 `404`。

需要持續同步商品時，請使用[游標同步](#cycle-protocol)，不要依靠一般頁碼列表。篩選參數見具體接口；一般讀取服務忽略未知業務欄位，寫入服務拒絕未知業務欄位；歷史和同步讀取採用更嚴格的驗證。

<details id="field-formats">
<summary>欄位格式</summary>

| 欄位 | 使用方式 |
| --- | --- |
| 數值型資源 ID | 正整數，最大 `2147483647`。 |
| 範本、分組、欄位、版本 ID | 字串，原樣保存，不假定為 UUID。 |
| 素材 ID | 使用素材查詢回傳的 `id`（FilePath ID），不能替換成 AssetObject ID 或商品關聯 ID。 |
| 分類 `iconAssetId` | 使用分類圖示的識別碼（CategoryIconAsset）。 |
| `size` | 十進位字串或 `null`，避免大型檔案位元組數失去精度。 |
| 日期 | RFC 3339 字串或 `null`；同步時間戳記保留完整六位小數。 |
| 商品 SKU | API 欄位名稱為 `spu`。 |

舊版或無法解析的商品媒體可能回傳 `id: null`。有效的媒體引用不會被截斷。預覽和下載連結的使用方式見[媒體連結](#media-and-expiry)。

所有回應攜帶 `Cache-Control: private, no-store`。JSON 操作和錯誤使用 `application/json`。請求大小、批次數量等上限見[請求限制](#error-catalog)。

</details>

<details id="write-preconditions">
<summary>並行更新</summary>

讀取品牌、分類、模板或商品時儲存強 `ETag`（包括引號），更新、狀態變更或刪除時可放入 `If-Match`。回傳 `412 precondition_failed` 時重新讀取並核對；省略時後一次寫入覆蓋前一次。分享、歷史和下載記錄不使用 ETag。

</details>

<details id="atomic-create-replay">
<summary>建立與下載重試</summary>

建立資源可使用 `Idempotency-Key`。鍵按團隊、API Key 和操作區分，最長 255 個字元，不能為空白或含控制字元。24 小時內以相同鍵和輸入重試；變更輸入回傳 `409 idempotency_key_reused`。資源建立重播首次非媒體結果，媒體按目前權限重建。下載重試只重用業務記錄，仍重新授權並傳輸目前檔案。

</details>

<details id="error-catalog">
<summary>請求限制與錯誤處理</summary>

請求本文最多 1 MiB。寫入服務拒絕未知業務欄位，一般讀取服務忽略未知業務欄位；歷史和同步讀取服務嚴格驗證。此規則依服務區分，與 HTTP 方法無關。

| 回傳結果 | 處理方式 |
| --- | --- |
| 401 / 403 | 檢查密鑰、協作者角色及資源可見性。 |
| 404 | 資源不存在、已刪除或不可存取，核對 ID。 |
| 422 `validation_failed` | 修正輸入；若有 `details`，讀取 `field` 和 `message`。 |
| 409 `sku_in_use` / `name_in_use` | 變更衝突的 SKU 或名稱；軟刪除商品的 SKU 仍被占用。 |
| 409 `mutation_response_unavailable` | 變更已提交或重播，按 `mutationOutcome` 核對；不要盲目重新建立。 |
| 503 `write_conflict` | 變更已回滾，依 `Retry-After: 1` 等待後重試。 |
| 413 | 縮小請求本文或下載數量／大小。 |

透過回應標頭 `X-Request-Id` 或 JSON 中的 `requestId` 排查請求。下載錯誤含 `mutationOutcome` 時，記錄已經提交，重試沿用原冪等鍵。

</details>

## 分類

<details id="category-rules">
<summary>分類樹與刪除</summary>

同級名稱必須唯一，父分類必須屬於同一品牌。分類最多 10 級，每個品牌最多 5000 個未刪除節點。`sortOrder` 是從零開始的同級位置；建立或移動時省略則附加，同父層更新時省略則保持位置。改名或移動會更新後代路徑。

建立時，只有商品庫預設模板未綁定品牌或已綁定目前品牌，才新增直接模板綁定；否則仍建立成功，按祖先分類、品牌、商品庫預設模板查找。刪除會軟刪除整棵子樹；其中有未刪除商品時回傳 `409 category_has_products`，不執行刪除。

</details>

## 信息模板

<details id="template-groups">
<summary>分組 groups</summary>

`groups` 包含 1–200 個分組，一個模板的欄位總數最多為 200。

| 欄位 | 類型 | 說明 |
| --- | --- | --- |
| `id` | string | 現有分組必填，1–128 個字元，必須屬於本模板；新分組不傳。 |
| `name` | string | 必填，1–128 個字元，去除首尾空白。 |
| `fields` | array | 必填，分組中的欄位，見下表。 |

現有分組保持原有順序，新分組按提交順序附加。分組不接受 `sortOrder` 或 `isDefault`。預設分組由伺服器指定，不能刪除。

</details>

<details id="template-fields">
<summary>欄位 fields</summary>

新欄位必須提供 `key`、`name` 和 `type`。更新現有欄位時必須傳 `id`。類型不變時，省略的屬性保留原值，`sortOrder` 除外；變更 `type` 時，`config` 會按目標類型遷移，必要時須明確提供新設定。

| 欄位 | 類型 | 說明 |
| --- | --- | --- |
| `id` | string | 現有欄位必填，1–128 個字元，必須屬於目前分組；新欄位不傳。 |
| `key` | string | 新欄位必填，1–64 個字元，須為唯一的有效識別符；既有欄位不能修改。 |
| `name` | string | 新欄位必填，1–128 個字元。 |
| `type` | string | 新欄位必填，支援的類型見下方設定表。 |
| `required` | boolean | 選填；新欄位預設為 `false`。 |
| `placeholder` | string 或 null | 選填，最多 255 個字元；新欄位預設為 `null`。 |
| `sortOrder` | integer | 選填，同組內唯一的非負整數；省略時使用欄位在陣列中的位置。 |
| `config` | object | 按欄位類型填寫，見下方設定表；新欄位省略時使用 `{}`，但仍須滿足該類型的設定要求。 |
| `typeChangeConfirmed` | boolean | 選填；允許但需要確認的類型變更須傳 `true`。 |

建立時會自動加入名稱、SKU 和主圖三個受保護欄位，因此最多可新增 197 個自訂欄位。第一個分組的自訂欄位排列在這三個欄位之後，傳入的 `sortOrder`（省略時為陣列位置）會增加 3。替換定義時須保留這些欄位的 `id`，以及類型、必填標記和設定。欄位不能移到其他分組。

新欄位只能是自訂欄位，不能使用保留的系統 key。`isSystemField` 和 `systemKey` 不能用於建立或重新分配系統身分；更新時保留原值。未知的分組或欄位屬性會被拒絕。

</details>

<details id="field-configuration">
<summary>欄位設定 config</summary>

設定由欄位的 `type` 決定。例如，文字欄位使用 `{}`，貨幣和選項欄位需要額外設定。

| 欄位類型 | config 設定 |
| --- | --- |
| `text`、`textarea`、`email`、`phone`、`url`、`color`、`date`、`dateRange` | 使用 `{}`，不接受其他設定。 |
| `number` | 選填 `unit`，字串。 |
| `currency` | 必填 `code`、`symbol`（非空字串）和 `decimals`（0–4 的整數）。 |
| `richtext` | 必填 `mode`，取值為 `html` 或 `delta`。 |
| `select`、`radio`、`checkbox` | 必填非空 `options` 陣列。每項見下表，`value` 不得重複。 |
| `image`、`file` | 選填 `maxCount`（大於等於 1 的整數）、`maxSizeMB`（大於 0 的數字）和 `accept`（字串陣列）。 |

每個 `options` 元素包含：

| 欄位 | 類型 | 說明 |
| --- | --- | --- |
| `value` | string | 必填，非空，選項的唯一值。 |
| `label` | string | 必填，非空，顯示名稱。 |
| `sortOrder` | integer | 必填，非負整數。 |
| `archived` | boolean | 選填，是否封存該選項。 |

系統欄位的可用設定是 `customPlaceholder`（選填字串，最多 255 個字元）；品牌、分類系統欄位不接受自訂選項。受保護系統欄位的設定不能變更。

空設定和系統設定拒絕未知屬性；其他設定及選項會移除未知屬性。完整機器可讀定義可下載 [OpenAPI JSON](/assets/developers/product-library/openapi.json)。

</details>

<details id="template-definition">
<summary>回傳的模板定義</summary>

模板詳情的 `groups` 和商品的 `templateDefinition.groups` 均包含分組與欄位。商品回傳的是建立時固定的版本，後續模板修改或刪除不會改變它；未綁定模板時，`templateDefinition` 可為 `null`。

分組固定回傳 `id`、`name`、`fields`，以及以下唯讀屬性：

| 欄位 | 類型 | 說明 |
| --- | --- | --- |
| `isDefault` | boolean | 是否為預設分組。 |
| `sortOrder` | integer | 分組順序。 |

每個欄位固定回傳 `id`、`key`、`name`、`type`、`required`、`placeholder`、`sortOrder`、`config`，以及以下屬性；不回傳寫入參數 `typeChangeConfirmed`。

| 欄位 | 類型 | 說明 |
| --- | --- | --- |
| `isSystemField` | boolean | 是否為系統欄位。 |
| `systemKey` | string 或 null | 系統身分：`name`、`sku`、`brand`、`category`、`description`、`mainImage`；自訂欄位為 `null`。 |

`placeholder` 可為 `null`。設定中的媒體引用會回傳安全的預覽資訊，不包含儲存路徑或憑證。讀取商品的固定模板定義不需要 `templates:read` 權限。

</details>

<details id="fields-Template">
<summary>Template 回傳欄位</summary>

| 字段名 | 類型 | 描述 |
| - | - | - |

| updatedAt | String | RFC 3339 時間字串；保留完整精度。|
| boundBrandIds | List&lt;Integer&gt; | 綁定的品牌 ID。每個元素：正整數 ID，最大 2147483647。 |
| boundCategoryIds | List&lt;Integer&gt; | 綁定的分類 ID。每個元素：正整數 ID，最大 2147483647。 |
| groups | List&lt;VersionGroup&gt; | 模板分組。嵌套字段：[範本分組與欄位](#template-definition) |

</details>

## 商品

<details id="template-pins-and-field-values">
<summary>模板版本與自訂欄位</summary>

商品建立時儲存模板版本。讀取 `templateDefinition` 解釋 `templateFields`；後續模板變更或刪除不影響這個版本，`updateProduct` 不能更換模板。`templateFields` 以固定版本中的欄位 ID 為鍵，更新時淺合併；`null` 清空單個欄位。

明確提供的 `templateId` 優先；否則，有 `categoryId` 時依次查找分類、祖先分類、品牌和商品庫預設模板。沒有分類時只考慮商品庫預設模板，即使傳入了品牌。

| 字段類型 | 輸入格式 |
| --- | --- |
| `number`、`currency` | JSON 數字 |
| `dateRange` | 起止日期字符串組成的有序數組 |
| `checkbox` | 選項值數組 |
| `image`、`file` | FilePath ID 數組，或 null |
| `richtext` | HTML 模式為字符串；delta 模式為 `{ "ops": [...] }` |

草稿可缺少必填值，但提交和合併後的欄位仍須滿足類型／選項規則；發布或編輯已發布商品會驗證完整商品。一次寫入的全部媒體引用合計最多 100 個，只接受本商品庫既有的 FilePath ID。媒體列表省略時保留，`[]` 清空；未傳 `coverAssetId` 時，首張 `imageAssetIds` 圖片成為封面。

</details>

<details id="cycle-protocol">
<summary>同步與檢查點</summary>

1. 首次使用 `"sync": "true"`，省略 `updatedAfter`；增量週期傳入上次完成的 `syncedUntil`。
2. 按商品 `id` 和 `updatedAt` 合併，保留較新版本。
3. 使用 `"sync": "true", "cursor": "<nextCursor>"` 跟隨 `nextCursor` 直到 null；即使 `data` 為空，也要繼續。
4. 完成後原樣儲存 `syncedUntil`，不要改用最後一筆商品的時間。

游標綁定密鑰、角色、商品庫、篩選條件和頁面大小；續頁時不要變更它們。更換授權或篩選條件要開始新週期；範圍擴大時重新完整同步。檢查點和同步 `updatedAt` 保留完整六位小數，不要用 JavaScript Date 截斷精度。每週期讀取目前狀態的 `[updatedAfter, syncedUntil)`，上界為首次請求時伺服器時間減 30 秒；長交易仍可能影響完整性，不提供每次變更的事件串流。

</details>

<details id="reconciling-removals">
<summary>清理已刪除或不可見的商品</summary>

同步不會回傳刪除事件。定期將本機商品 ID 交給[可見性介面](#operation-checkProductVisibility)，`not_visible` 時移除本機副本。該介面不檢查品牌、分類或搜尋等業務篩選；若只維護篩選後的副本，須定期完整核對篩選結果，或同步全部可見商品後在本機篩選。

</details>

<details id="media-and-expiry">
<summary>預覽與下載鏈接</summary>

展示商品媒體時使用 `previewUrl`。需要原文件時，檢查 `downloadUrl`，或使用下一節的下載接口；能預覽不等於有下載權限。

| 鏈接 | 返回條件 | 服務簽發鏈接的有效期上限 |
| --- | --- | --- |
| 派生預覽 | 具備相應查看權限 | 3600 秒 |
| 圖片原圖預覽回退 | 僅適用於圖片，`view_only` 也可能返回 | 300 秒 |
| `downloadUrl` | 關聯可解析且可見，`usable` 或更高角色，同時具備 `products:read` 和 `products:download` | 300 秒 |

所有服務簽發鏈接還受 API key 的到期時間限制。鏈接過期後重新獲取商品數據，不要將簽名 URL 當作素材 ID 保存。

<details id="product-media-fields">
<summary>封面、圖片和關聯素材返回哪些字段？</summary>

`cover` 是一個媒體對象，無封面時為 null；`images`、`relatedAssets` 為媒體對象數組。自定義圖片/文件值可為數組或 null，未填寫的字段可能省略。

| 字段 | 類型 | 說明 |
| --- | --- | --- |
| `id` | 整數或 null | 素材查詢返回的 ID（FilePath ID），不是 AssetObject ID 或商品素材關聯 ID |
| `name`、`mimeType` | 字符串或 null | 文件名、MIME 類型 |
| `size` | 字符串或 null | 十進制字節數，如 `"2048"`，不是 JSON 數字 |
| `width`、`height`、`duration` | 數字或 null | 媒體尺寸和時長 |
| `previewUrl` | URL 或 null | 用於展示的預覽地址；不可用時為 null |
| `downloadUrl` | URL 或 null，可省略 | 原文件地址；返回條件見上表 |
| `downloadUrlExpiresAt` | 時間字符串或 null，可省略 | 下載地址的到期時間，RFC 3339 格式 |

</details>

<details>
<summary>鏈接缺失、舊版媒體和外部預覽如何處理？</summary>

- 非圖片素材只返回派生預覽，原始 PDF、壓縮包和文檔不會作為預覽回退。素材庫素材查詢和模板配置只包含預覽。
- 缺少下載權限或關聯無法解析時，會省略 `downloadUrl` 和 `downloadUrlExpiresAt`；已授權但原文件不可用時，這些值可能為 null。
- 已存儲的外部 DAM 縮略圖或預覽，只對未設置過期時間的 API key 返回，並先排除已知原文件 URL。它們的有效期由第三方控制，不保證短有效期，也不保證校驗提供方簽名。
- API key 設置了 `expiresAt` 時，過期時間無法驗證的外部預覽返回 null。查詢參數中形似簽名的值不能作為可信的過期依據。
- 服務簽發的鏈接仍遵守上表限制；簽名失敗時不會返回原始存儲 URL。

</details>

### 獲取或同步商品列表

**接口路徑**： https://open.musedam.cc/api/muse/product-api

**請求方式**： POST

**接口描述**：普通分頁按 updatedAt/id 降序排序。sync: "true" 時按 (updatedAt,id) 升序排序，使用包含的下界和不包含的固定上界（PostgreSQL 時鐘減 30 秒）。全量掃描時省略 updatedAfter；請持續跟隨每個 nextCursor，即使 data 頁為空。游標綁定 key/角色/商品庫/篩選條件/pageSize/邊界。僅在遍歷完畢後原樣保存 syncedUntil；按 id 和 updatedAt 進行重放/去重。持續時間超過 30 秒安全窗口的事務屬於 v1 已接受的限制。見[同步說明](#cycle-protocol)。view_only/usable 僅可見已發佈商品。

所需角色：所有協作者角色。

**請求參數**：

| 參數名 | 類型 | 必填 | 描述 |

| updatedAfter | String | 否 | 請求本文欄位。僅在 sync: "true" 時使用。包含的下界；RFC3339 格式，使用 Z 或時區偏移，0..6 位小數，日曆日期/偏移須有效。請將 syncedUntil 作為字符串保存並復用。全量掃描時省略。格式：date-time |
| cursor | String | 否 | 請求本文欄位。不透明的續頁令牌，僅在 sync: "true" 時使用。綁定 key、角色、商品庫、邊界、篩選條件和每頁條數。續頁時省略其他參數，或重復傳入等價的值。最短 1 個字符；最長 8,192 個字符 |

**SyncPage**

| 字段名 | 類型 | 描述 |
| - | - | - |
| pageSize | Integer | 每頁數量。最小值：1；最大值：100 |
| syncedUntil | String | PostgreSQL 時鐘減 30 秒，在整個週期內固定。僅在 nextCursor 為 null 後原樣保存此字符串。格式：date-time；須匹配 `^\d{4}-\d\d-\d\dT\d\d:\d\d:\d\d\.\d{6}Z$` |
| nextCursor | String | 下一頁游標，掃描結束後為 null。最長 8,192 個字符；可為 null |
| hasMore | Boolean | 是否還有下一頁同步數據。 |

| id | Integer | 是 | 請求本文欄位。正的有符號 32 位資源 ID。正整數 ID，最大 2147483647。 |

## 下載

<details id="download-usage">
<summary>選擇檔案、匯出與記錄</summary>

先查詢商品下載候選，將回傳的 `key` 放入 `assetKeys`，或將原始 key 放入單檔請求本文欄位 `assetKey`；它不是 FilePath ID。原始檔案下載只有一個檔案時回傳該檔案，多個檔案時回傳 ZIP。每次選擇 1–100 個商品、最多 200 個檔案、合計不超過 500 MiB。

匯出使用 `kind: "export"`，格式為 xlsx（預設）、csv 或 json，不能傳 `assetKeys`。`includeAssetUrls` 預設 true。三種格式的主圖、關聯素材及自訂 image/file 儲存格均為**下載請求描述符陣列的 JSON 字串**，只有一個檔案也使用陣列，空儲存格為字串 `"[]"`。一般欄位不變。JSON 匯出仍是本地化業務列陣列，儲存格值為字串，而非巢狀描述符陣列；媒體儲存格需要另外解析。

每個描述符嚴格採用以下結構（`assetKey` 是原始 key，不做 URL 編碼）：

```json
[{"url":"https://open.musedam.cc/api/muse/product-api","method":"POST","body":{"service":"downloadProductAsset","id":40,"assetKey":"p40:a2"}}]
```

這是儲存格內部的 JSON 文字，而非整個匯出檔案。描述符不包含憑證或請求標頭。執行時先解析儲存格，再於執行階段加入使用者的 `Authorization: Bearer <APIKEY>` 和 `Content-Type: application/json` 請求標頭：

```js
const requests = JSON.parse(mediaCell);
for (const request of requests) {
  const response = await fetch(request.url, {
    method: request.method,
    headers: {
      Authorization: `Bearer ${apiKey}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify(request.body),
  });
  if (!response.ok) throw new Error(`Download failed: ${response.status}`);
  const file = await response.blob();
  // Save or process the original file here.
}
```

啟用時，API 媒體欄名使用本地化的 ` (download requests)`（下載請求）後綴取代 URL 標籤，自訂媒體欄位標籤也加入相同後綴。`locale` 影響系統標籤、狀態及該後綴，不改變使用者自訂標籤或內容。`includeAssetUrls: false` 時保留舊行為：主圖和關聯素材儲存格為空字串，自訂 image/file 儲存格為分號分隔的檔案名稱。API 匯出不再產生舊的 `/api/open/v1` URL。網頁、成員及分享匯出不變。給免登入訪客使用時應建立分享。

附件回應標頭 `X-Download-Record-Id` 是業務記錄 ID。`requested` 僅表示請求已接受，不表示傳輸或本機儲存完成。歷史包含團隊瀏覽器操作及其他 API Key 的操作；一般讀取、預覽和直接存取儲存下載 URL 不計入歷史。

**接口描述**：返回一個原文件、所選原文件的 ZIP，或 XLSX/CSV/JSON 業務表格導出。需要 usable 及以上角色的當前讀取和下載權限；usable 只能訪問已發佈商品。已接受的操作在交付前記入記錄。匯出媒體儲存格預設包含 POST 下載請求描述符陣列的 JSON 字串，執行時需加入 Bearer 驗證，詳見[選擇檔案、匯出與記錄](#download-usage)。每次接受的提取有自己的業務記錄。可選 Idempotency-Key 在 24 小時內保留一條記錄，每次重試仍重新鑒權並傳輸當前內容。商品讀取、預覽和舊存儲 downloadUrl 的訪問不會由此操作記入記錄。

所需角色：usable、editable 或 manage。

**請求參數**：

以下業務欄位與 `service` 同層，直接放入 JSON 請求本文，不要使用 `params` 或 `data` 包裝。`If-Match` 和 `Idempotency-Key` 仍為 HTTP 請求標頭，不是業務欄位。

| 參數名 | 類型 | 必填 | 描述 |
| - | - | - | - |
| service | String | 是 | 服務識別碼，固定為 `downloadProducts`. |
| Idempotency-Key | String | 否 | 選填請求標頭；同一鍵和輸入在 24 小時內重試，詳見[冪等重試](#atomic-create-replay)。 |

**ProductDownloadCreate參數說明**：

assets 省略 assetKeys 時選擇全部原文件，否則僅選擇提供的當前 key。export 不接受 assetKeys，並生成本地化業務表格。format、includeAssetUrls 和 locale 僅影響導出；素材下載接受這些選項但不據此改變交付內容。includeAssetUrls 為 true（預設）時，媒體儲存格是下載請求描述符陣列的 JSON 字串，而非 URL。解析、欄名及 false 模式詳見[匯出儲存格約定](#download-usage)。locale 影響系統標籤、狀態及下載請求後綴，不改變使用者自訂標籤或內容。

不接受未定義字段。

| 字段名 | 類型 | 必填 | 描述 |
| - | - | - | - |
| kind | String | 是 | 允許值：assets、export |
| productIds | List&lt;Integer&gt; | 是 | 最少 1 項；最多 100 項；每個 ID 為正整數，最大 2147483647。 |
| assetKeys | List&lt;String&gt; | 否 | 每個元素：最短 1 個字符；最長 256 個字符；最少 1 項；最多 200 項 |
| format | String | 否 | 允許值：xlsx、csv、json；默認值："xlsx" |
| includeAssetUrls | Boolean | 否 | 默認值：true |
| locale | String | 否 | 允許值：zh-CN、en-US、zh-TW、ja-JP、ko-KR、pt-BR、ru-RU、id-ID、fr-FR、it-IT、pl-PL、vi-VN、tr-TR、th-TH、de-DE、es-ES、hi-IN；默認值："zh-CN" |

**響應參數**： `200`。成功時回傳附件，回應本文為檔案位元組；JSON 僅用於交付前的錯誤。

響應頭：`Content-Disposition`、`X-Download-Record-Id`、`X-Idempotency-Replayed`

請求示例：

```bash
curl --request POST 'https://open.musedam.cc/api/muse/product-api' \
  --header 'Authorization: Bearer your_api_key' \
  --header 'Content-Type: application/json' \
  --data-raw '{
  "service": "downloadProducts",
  "kind": "export",
  "productIds": [
    40
  ],
  "format": "xlsx",
  "includeAssetUrls": true,
  "locale": "zh-CN"
}' \
  --output products.xlsx
```

### 下載一個商品原文件

**接口路徑**： https://open.musedam.cc/api/muse/product-api

**請求方式**： POST

**接口描述**：透過請求本文中的原始候選 key 獲取當前商品的一個原文件。需要 Bearer 請求頭以及當前讀取/下載授權；URL 不含 API key 密鑰。交付前創建業務記錄。可選的 24 小時冪等機制與 `downloadProducts`使用不同作用域，復用記錄時仍重新鑒權並傳輸當前字節。

所需角色：usable、editable 或 manage。

**請求參數**：

以下業務欄位與 `service` 同層，直接放入 JSON 請求本文，不要使用 `params` 或 `data` 包裝。`If-Match` 和 `Idempotency-Key` 仍為 HTTP 請求標頭，不是業務欄位。

| 參數名 | 類型 | 必填 | 描述 |
| - | - | - | - |
| service | String | 是 | 服務識別碼，固定為 `downloadProductAsset`. |
| id | Integer | 是 | 請求本文欄位。正的有符號 32 位資源 ID。正整數 ID，最大 2147483647。 |
| assetKey | String | 是 | 請求本文欄位。商品下載候選列表返回的原始選擇 key，不做 URL 編碼；它不是 FilePath 或 AssetObject ID。最短 1 個字符；最長 256 個字符 |
| Idempotency-Key | String | 否 | 選填請求標頭；同一鍵和輸入在 24 小時內重試，詳見[冪等重試](#atomic-create-replay)。 |

**響應參數**： `200`。成功時回傳附件，回應本文為檔案位元組；JSON 僅用於交付前的錯誤。

響應頭：`Content-Disposition`、`X-Download-Record-Id`、`X-Idempotency-Replayed`

請求示例：

範例將下載候選原始 key `p40:a2` 放入 JSON 請求本文的 `assetKey`，不做 URL 編碼。請使用您的下載候選列表返回的 key，它不是 FilePath 或 AssetObject ID。

```bash
curl --request POST 'https://open.musedam.cc/api/muse/product-api' \
  --header 'Authorization: Bearer your_api_key' \
  --header 'Content-Type: application/json' \
  --data-raw '{
  "service": "downloadProductAsset",
  "id": 40,
  "assetKey": "p40:a2"
}' \
  --output product-asset.bin
```

Content-Type: application/octet-stream
Content-Disposition: attachment
