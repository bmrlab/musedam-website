## 常见错误及处理方法

### API 认证错误

| 错误码 | 错误描述 | 处理方法 |
|-|-|-|
| MB100002 | 没有权限访问该资源 | 检查 API Key 是否正确，是否具有访问该资源的权限 |
| 401 | Unauthorized | API Key 无效或已过期，需要更新 API Key |

### 请求参数错误

| 错误码 | 错误描述 | 处理方法 |
|-|-|-|
| MB100001 | 请求参数不正确 | 检查请求参数格式、类型是否符合API要求 |
| MB100003 | 资源不存在 | 检查请求的资源ID是否存在或已被删除 |

### 业务逻辑错误

| 错误码 | 错误描述 | 处理方法 |
|-|-|-|
| MB100004 | 资源不支持该操作 | 检查操作是否适用于当前资源类型 |
| MB100005 | 业务处理失败 | 根据错误信息调整业务逻辑或重试 |

### 系统级错误

| 错误码 | 错误描述 | 处理方法 |
|-|-|-|
| MS100001 | 系统异常 | 稍后重试，如持续出现请联系技术支持 |
| MS100003 | 系统繁忙 | 实施请求限流，延迟重试 |

## 排查顺序

1. 检查 HTTP 状态、业务 `code` 与 `message`，保存 `traceId`。
2. 验证域名、请求方法、请求体类型和密钥授权范围。
3. 检查资源是否属于当前企业，及相应产品能力是否已开通。
4. 对临时系统故障使用有上限的重试；参数或权限错误修复后再请求。

原始示例中的成功业务码存在 `0`、`"0"` 与 `"200"` 等写法。请按具体接口确认成功判断逻辑，不要仅凭 HTTP 200 判定业务成功。
