普通的 `GET /api/product/products?page=...` 列表用于浏览，而非同步。首次全量复制和每个增量周期都应使用
`GET /api/product/products?sync=true`。所有请求都需要 `products:read`，并使用与普通商品读取相同的角色和商品库可见性规则。

## 周期协议

1. 以 `sync=true` 开始，可选 `pageSize`（默认 20，上限 100），以及可选的商品筛选参数 `search`、`brandId`、`categoryId` 和 `status`。全量同步时省略 `updatedAfter`。增量周期时，将其设置为上一个已完成周期的 `syncedUntil` 字符串，且不改变其精度。
2. 按 `id` 和 `updatedAt` 合并返回的商品，保留较新的版本。
3. 使用 `sync=true&cursor=...` 跟随 `pagination.nextCursor`，直到其为 null。当所选商品在投影期间变为不可见时，空数据页仍可能带有下一页游标。请继续跟随该游标。
4. 将已完成周期的 `syncedUntil` 原样保存，作为下一个检查点。不要用最后一个商品的时间戳替代它。

同步分页的结构如下：

```json
{
  "pageSize": 20,
  "syncedUntil": "2026-10-08T12:00:00.123456Z",
  "nextCursor": null,
  "hasMore": false
}
```

游标是不透明且带版本的。它保留精确的下界、上界、最后的 `(updatedAt, id)` 位置、页大小和筛选条件。后续请求可以省略筛选条件、页大小和
`updatedAfter`；将沿用已保存的值。如果重复提供，它们必须与原始周期一致（下界接受等价的 RFC 3339 偏移量）。更改其中任何一项、在其他 API key 或角色下使用游标、游标数据格式错误、重复的同步参数，或提供 `page`，均返回 `422 validation_failed`。更换 key 或角色后请重新开始周期。
`cursor` 和 `updatedAfter` 需要 `sync=true`；不支持的 sync 值也会被拒绝。`sync=false` 使用普通的浏览列表。

`updatedAfter` 接受带时区（`Z` 或数字偏移量）的 RFC 3339 时间戳，小数部分为零到六位。无效的日历日期、无效的偏移量、超过六位的精度，以及晚于安全上界的下界，均返回 `422 validation_failed`。返回的检查点和同步商品的 `updatedAt`
值使用 UTC，且恰好包含六位小数。请在存储中原样保留这些字符串；JavaScript Date 无法保留其完整精度。

## 交付与并发变更

每个周期读取 `[updatedAfter, syncedUntil)`，先按 `updatedAt` 再按 `id` 排序，均为升序。下界包含在内，上界不包含在内。恰好位于 `syncedUntil` 的行属于下一个周期。第一页根据 PostgreSQL 时钟减去 30 秒的具名安全窗口来计算上界。之后的每一页都保留这一精确的上界。

该窗口超过 API 15 秒的写入事务预算，可将最近未提交的更新排除在当前周期之外。保持打开时间超过安全窗口的事务仍是一项限制。同步为至少一次（at-least-once）：将商品移动到当前游标之后的更新可能导致再次交付。请按 ID 和更新时间合并，并使用原始游标重试失败的页。

分页使用 PostgreSQL 原始微秒值。一个短暂的可重复读事务会将每个选中的时间戳与其商品快照配对，然后在媒体投影之前关闭。响应会重新检查 key 权限和商品当前的可见性。已删除或新变为不可见的选中商品会被省略，而不会导致整页失败，且游标仍会越过这些选中的行前进。较早页面中的删除不会使后续行偏移出结果。

## 核对移除

`POST /api/product/products/visibility` 只接受以下请求体：

```json
{ "ids": [42, 43] }
```

它接受零到 100 个正整数商品 ID（最大 2147483647），保留输入顺序和重复出现的项。其 `data` 不包含任何商品内容：

```json
[
  { "id": 42, "visibility": "visible" },
  { "id": 43, "visibility": "not_visible" }
]
```

对于仅能查看已发布商品的角色，草稿、已删除、属于其他商品库以及不存在的 ID 都会得到相同的 `not_visible` 值。可编辑和可管理角色还可以看到草稿。只返回提交的 ID；不存在移除事件流或草稿发现端点。请定期针对集成方已存储的 ID 调用此接口，例如在每个周期完成之后。无效的请求体、非整数 ID、未知的请求体字段以及超过 100 个的批次，均返回 `422 validation_failed`。
