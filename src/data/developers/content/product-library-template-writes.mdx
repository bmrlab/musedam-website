所有路径均使用 `/api/product`。写入需要 `manage` API Key 协作者权限。

## 创建与更新

创建模板时，提供名称和至少一个分组。以下示例添加一个可选的颜色字段：

```json
{
  "name": "Catalog",
  "groups": [
    {
      "name": "Basics",
      "fields": [
        { "key": "color", "name": "Color", "type": "text" }
      ]
    }
  ]
}
```

`POST /product-info-templates` 返回 `201`；`PATCH /product-info-templates/{id}` 返回 `200`。两者均返回模板详情和 `ETag`。名称为 1–30 个字符，描述最多 50 个字符。

更新时，省略 `groups` 会保留原有定义；提供 `groups` 会替换完整定义。保留现有分组和字段的 `id`，新分组和字段不传 `id`。省略的现有分组和字段会被软删除。

<details>
<summary>绑定、默认模板和版本规则</summary>

- `boundBrandIds`、`boundCategoryIds` 只替换所提供维度的绑定，省略则保持不变，每个数组最多 10,000 个 ID。ID 必须属于同一商品库；选定品牌时，分类必须属于这些品牌。已绑定其他模板的 ID 会转移到本模板。
- `isLibraryDefault: true` 将本模板设为商品库默认模板；`false` 仅清除本模板的默认状态，省略则保持不变。
- 每次成功创建或更新都会保存一个新版本。只支持 `syncStrategy: "newOnly"`，`syncAll` 返回 `422 validation_failed`。已有商品继续使用创建时的模板版本，字段定义和值不随模板更新而变化。

</details>

`POST` 可通过 `Idempotency-Key` 安全重试，更新可通过 `If-Match` 检查版本，详见[写入约定](./product-library-write-conventions)。完整顶层参数见[创建模板](./product-library-reference#operation-createTemplate)和[更新模板](./product-library-reference#operation-updateTemplate)。

## 分组 groups

`groups` 包含 1–200 个分组，一个模板的字段总数最多为 200。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 现有分组必填，1–128 个字符，必须属于本模板；新分组不传。 |
| `name` | string | 必填，1–128 个字符，去除首尾空白。 |
| `fields` | array | 必填，分组中的字段，见下表。 |

现有分组保持原有顺序，新分组按提交顺序追加。分组不接受 `sortOrder` 或 `isDefault`。默认分组由服务器指定，不能删除。

## 字段 fields

新字段必须提供 `key`、`name` 和 `type`。更新现有字段时必须传 `id`，省略的属性保留原值，`sortOrder` 除外。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 现有字段必填，1–128 个字符，必须属于当前分组；新字段不传。 |
| `key` | string | 新字段必填，1–64 个字符，须为唯一的有效标识符；已有字段不能修改。 |
| `name` | string | 新字段必填，1–128 个字符。 |
| `type` | string | 新字段必填，支持的类型见下方配置表。 |
| `required` | boolean | 可选；新字段默认为 `false`。 |
| `placeholder` | string 或 null | 可选，最多 255 个字符；新字段默认为 `null`。 |
| `sortOrder` | integer | 可选，非负整数；省略时使用字段在数组中的位置。 |
| `config` | object | 按字段类型填写，见下方配置表；新字段省略时使用 `{}`，但仍须满足该类型的配置要求。 |
| `typeChangeConfirmed` | boolean | 可选；允许但需要确认的类型变更须传 `true`。 |

<details>
<summary>系统字段和更新限制</summary>

创建时会自动加入名称、SKU 和主图三个受保护字段，因此最多可新增 197 个自定义字段。替换定义时须保留这些字段的 `id`，以及类型、必填标记和配置。字段不能移到其他分组。

新字段只能是自定义字段，不能使用保留的系统 key。`isSystemField` 和 `systemKey` 不能用于创建或重新分配系统身份；更新时保留原值。未知的分组或字段属性会被拒绝。

</details>

## 字段配置 config

配置由字段的 `type` 决定。例如，文本字段使用 `{}`，货币和选项字段需要额外配置。

<details>
<summary>查看各字段类型的配置</summary>

| 字段类型 | config 配置 |
| --- | --- |
| `text`、`textarea`、`email`、`phone`、`url`、`color`、`date`、`dateRange` | 使用 `{}`，不接受其他配置。 |
| `number` | 可选 `unit`，字符串。 |
| `currency` | 必填 `code`、`symbol`（非空字符串）和 `decimals`（0–4 的整数）。 |
| `richtext` | 必填 `mode`，取值为 `html` 或 `delta`。 |
| `select`、`radio`、`checkbox` | 必填非空 `options` 数组。每项见下表，`value` 不得重复。 |
| `image`、`file` | 可选 `maxCount`（大于等于 1 的整数）、`maxSizeMB`（大于 0 的数字）和 `accept`（字符串数组）。 |

每个 `options` 元素包含：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `value` | string | 必填，非空，选项的唯一值。 |
| `label` | string | 必填，非空，显示名称。 |
| `sortOrder` | integer | 必填，非负整数。 |
| `archived` | boolean | 可选，是否归档该选项。 |

系统字段的可用配置是 `customPlaceholder`（可选字符串，最多 255 个字符）；品牌、分类系统字段不接受自定义选项。受保护系统字段的配置不能变更。

空配置和系统配置拒绝未知属性；其他配置及选项会移除未知属性。完整机器可读定义可下载 [OpenAPI JSON](/assets/developers/product-library/openapi.json)。

</details>

## 返回的模板定义

模板详情的 `groups` 和商品的 `templateDefinition.groups` 均包含分组与字段。商品返回的是创建时固定的版本，后续模板修改或删除不会改变它；未绑定模板时，`templateDefinition` 可为 `null`。

<details>
<summary>查看分组与字段的返回属性</summary>

分组固定返回 `id`、`name`、`fields`，以及以下只读属性：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `isDefault` | boolean | 是否为默认分组。 |
| `sortOrder` | integer | 分组顺序。 |

每个字段固定返回 `id`、`key`、`name`、`type`、`required`、`placeholder`、`sortOrder`、`config`，以及以下属性；不返回写入参数 `typeChangeConfirmed`。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `isSystemField` | boolean | 是否为系统字段。 |
| `systemKey` | string 或 null | 系统身份：`name`、`sku`、`brand`、`category`、`description`、`mainImage`；自定义字段为 `null`。 |

`placeholder` 可为 `null`。配置中的媒体引用会返回安全的预览信息，不包含存储路径或凭据。读取商品的固定模板定义不需要 `templates:read` 权限。

</details>

## 前置条件与删除

`PATCH` 和 `DELETE` 接受可选的 `If-Match`。原样传入读取模板时的 `ETag`；值过期时返回 `412 precondition_failed`，模板保持不变。省略时，后一次写入覆盖前一次。

`DELETE /product-info-templates/{id}` 软删除模板并移除品牌、分类绑定，保留历史版本和商品的固定版本。成功返回 `200`，包含已删除的 ID 和 `ETag`。

<details>
<summary>删除默认模板与错误处理</summary>

删除商品库默认模板时，必须提供 JSON 字段 `replacementForLibraryDefault`，值为同一商品库中另一个未删除模板的 ID，或用 `null` 清除默认模板。省略时返回 `409 default_template_replacement_required`。删除非默认模板无需请求体。

无效定义、引用、受保护字段变更或重复字段 key 返回 `422 validation_failed`；重复的未删除模板名称返回 `409 name_in_use`；模板不存在或不属于当前商品库时返回 `404 not_found`。

</details>
